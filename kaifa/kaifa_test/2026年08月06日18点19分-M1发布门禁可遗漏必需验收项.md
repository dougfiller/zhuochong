## 1. 设计与正确性

### [P1] 必需 AC 集由输入自报，缺少全部 M1 验收项仍可错误放行

- 方案证据：`kaifa/kaifa_plan/2026年08月06日18点08分-执行M1自动化Windows实机和Work Review回归门禁.md:33` 要求所有当前适用的 `AC-BASE`、`AC-WX`、`AC-PET` 通过才能产出 `pass`；`:118` 要求 after 矩阵逐项记录稳定行。
- 代码证据：`kaifa/kaifa_test/verify_m1_release_gate.py:169-173` 只读取文档自身的 `required_ac_ids`，再检查其是否为 after matrix 的子集；没有固定 `AC-WX-01` 至 `AC-WX-06` 和 `AC-PET-01`、`AC-PET-02` 的必需集合，也没有要求这八行存在。
- 可复现实测：从 `fixtures/m1_gate/pass.json` 在内存中删除全部 `AC-WX-*` after-matrix 行，并将 `required_ac_ids` 置为空后调用 `validate`，输出为 `omitted_required_ac=pass`，且 `failures=[]`、`blockers=[]`。该探针不写入任何文件。
- 影响：未来证据 JSON 只要保留所有 `BASE-*` 行、候选关联、四个 Windows 场景和计数，即可遗漏 M1 capture/OCR/profile/copy/桌宠等必须验收项而声明 `pass`。这会绕过本步骤的发布门禁，而不是仅降低报告完整性。

## 修改与验收指南（仅限本报告问题）

1. 在 `verify_m1_release_gate.py` 中定义不可由 JSON 覆盖的必需集合：`AC-WX-01`—`AC-WX-06` 与 `AC-PET-01`、`AC-PET-02`；要求 after matrix 恰有这些稳定 ID，并全部为 `pass` 且各自引用已关联的证据。M2-only 行仍只允许 `conditional-not-enabled`，不可计入 M1 成功。
2. 增加回归 fixture：分别删除一个 AC-WX、一个 AC-PET，以及把 `required_ac_ids` 置空；三者都必须得到 `blocked`（或契约格式错误对应的 `fail`），绝不能为 `pass`。将 `pass.json` 扩展为完整的八项 M1 AC，避免它掩盖缺项。
3. 保持候选 commit、NSIS SHA-256 和 batch ID 的现有交叉关联；不要为修复 P1 放宽 Windows 四场景、零禁止 capability、台账或 before-baseline 规则，也不要新增产品 command、网络、MCP/Bot、输入/发送能力。
4. 修复后复跑本报告中的四个现有 fixture、三个新增缺 AC fixture、当前 after-gate 和 before-baseline verifier。只有完整同批 Windows/自动化/许可事实全部存在且 runner 对缺项变体可靠阻断后，才可重新审查发布门禁；在此之前维持 `blocked`，不建议合并或发布。
