## 1. 设计与架构

### [P1] Hybrid 查询缺少跨 vector/FTS 的同一 catalog 代际校验

**证据**

- `desktop/src-tauri/src/knowledge/embedding.rs:332-377` 先读取一次 active frozen config，随后分别调用 `search_active_vectors()` 和 `search_active_fts()`，之后直接融合结果。
- `desktop/src-tauri/src/knowledge/store.rs:1433-1437` 的二次校验只覆盖单次 vector scan 的开始/结束；它不能覆盖 vector 返回后、FTS 查询前发生的 catalog 切换。
- `search_active_hybrid()` 在 RRF 返回前没有再次读取并比较最初的 `catalog_generation + index_generation_id`，FTS hit 也没有携带供调用方核对的 generation token。

**影响**

步骤 22 开始允许激活新 generation 后，如果 catalog 恰好在 vector 查询结束与 FTS 查询开始之间切换，vector hits 可以来自 generation A，FTS hits 来自 generation B，最终仍被融合并返回。这违反方案中“查询期间切换必须丢弃结果、不得混合两个 generation”的 fail-closed 要求。

**修改指南**

1. 以第一次 `read_active_embedding_config()` 得到的 `catalog_generation + index_generation_id` 作为整次 hybrid 请求的 expected token。
2. 让 vector 与 FTS Store 查询都显式约束 expected index generation，或让两者返回实际 token 并由 orchestrator 核对。
3. 在 RRF 前再次读取 active token；任何一次 token 不一致都返回 `KB_RETRIEVAL_FAILED`，不得返回部分 hits。
4. 增加可控并发测试：在 vector 完成与 FTS 开始之间切换 catalog，断言整次查询失败且没有混合 hit；同时覆盖切换发生在 HTTP probe、vector scan 和 FTS scan 各阶段。

### [P2] 高层构建/查询 orchestration 没有行为测试

**证据**

- `desktop/src-tauri/src/knowledge/embedding.rs:478-680` 的自动测试只覆盖 endpoint 字符串、DNS pin、redirect、timeout/unavailable 和纯 `fuse_hybrid()`。
- 本次 `cargo test ... knowledge::` 与 `cargo check` 均明确报告 `probe_and_freeze_candidate`、`index_building_generation`、`search_active_hybrid`、`audit_call` 未使用。

**修改指南**

使用临时 `KnowledgeStore`、可注入 resolver/client 或受控 loopback fake server，增加三个高层行为测试组：candidate probe/freeze、building resume/write、active hybrid。至少覆盖 count/dimension/fingerprint 错误、1/8/32/33 batch、部分批次续作、catalog 切换和错误码映射；不要用静态字符串门禁替代这些行为测试。

## 3. 正确性与测试

### [P1] Store 接受零向量和非单位向量，active scan 会把它们当作有效余弦向量

**证据**

- `desktop/crates/core/src/semantic.rs:46-61` 的 `decode_embedding_exact()` 只检查精确字节长度与 finite，不检查向量为空、零模或单位范数。
- `desktop/src-tauri/src/knowledge/store.rs:1331-1335` 的 `write_build_embeddings()` 只调用上述 exact decoder，因此 `[0.0; dimension]` 和 `[2.0, 0.0, ...]` 都会被写入。
- `desktop/src-tauri/src/knowledge/store.rs:1414-1429` 的 active scan 同样只 exact decode 后直接点积；零向量不会失败，非单位向量会把“点积”误当余弦并扭曲排序。
- 现有 Store 测试 `embedding_store_is_frozen_resumable_and_exact_blob_fail_closed` 只覆盖 NaN 和多 1 个尾字节，没有覆盖零向量、非单位向量、短字节、多 2/3/4 字节或完整的错误维度。

**影响**

Store API 本身不能保证 frozen generation 的 embedding 完整性。当前 orchestrator 会先 strict normalize，但任何后续调用者、异常写入或数据库损坏都可能让无效向量进入 ready generation；查询不会按计划整次 fail-closed，且非单位向量会产生错误排名。

**修改指南**

1. 在 Store 写入边界和 active 读取边界增加知识领域专用校验：dimension 精确、全部 finite、L2 norm 大于 epsilon，并在容差内等于 1。
2. 读取已存 BLOB 时不要静默归一化损坏数据；应返回 `KB_RETRIEVAL_FAILED`，交由后续重建流程处理。
3. 增加 table-driven 行为测试：NULL、零向量、NaN、Inf、少 1、多 1/2/3/4、另一完整 dimension、非单位 finite 向量；任一坏行必须使整次 scan 失败。
4. 增加多行事务测试，证明一行 hash/vector 不合法时整批不写。

## 4. 安全性

### [P2] 模型 fingerprint 对重复 exact model 记录的 fail-closed 不完整

**证据**

- `desktop/src-tauri/src/knowledge/embedding.rs:169-183` 在统计 matches 前用 `filter_map` 丢弃 digest 缺失、非字符串或为空的 exact-name candidate。
- 当 `/api/tags` 同时返回两个同名 model，其中一个 digest 合法、另一个 digest 缺失/为空时，当前 `matches.len()` 仍为 1，代码会接受该 fingerprint。
- 技术方案要求“digest 缺失或多个候选都 fail-closed”。现有测试没有构造重复 exact-name 或缺失 digest 响应。

**修改指南**

先收集所有 `name == requested_model` 的 candidate，并要求 candidate 数精确为 1；随后再要求该唯一 candidate 的 digest 是非空字符串。增加零个、一个、两个同名、同名但缺失/空/非字符串 digest 的 table-driven HTTP parser 测试。

- endpoint 对 scheme/userinfo/path/query/fragment、普通私网、公网和 127.0.0.2 的拒绝测试通过。
- `localhost` 混合 DNS 拒绝、一次解析并 pin、redirect none、timeout/unavailable 在沙箱外 loopback 测试中通过。
- 没有发现新增 API key、Authorization、remote upload、agent 或 bot 依赖进入 knowledge embedding 模块。
