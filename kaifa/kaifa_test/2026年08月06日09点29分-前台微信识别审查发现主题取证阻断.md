# 前台微信识别和版本化布局兼容性实现审查（2026-08-06 09:29 +0800）

## 审查结论

**结论：不通过，禁止进入以可用 Windows profile 为前提的后续阶段或建议合并。**

本次实现维持了当前空 catalog 的 fail-closed 行为，且 macOS 下的纯 Rust 校验通过；但是实际 Windows 前台证据读取固定产生 `theme: None`，而 profile 匹配把缺失主题作为拒绝条件。因此，在未来填入任意已验证并启用的 production profile 后，真实 Windows 路径仍永远不能返回 `WechatWindowIdentity`。现有成功测试通过手工构造 `Some("light")` 绕过了该实际读取路径，不能证明功能可用。

审查范围仅限 LOOF run `20260806-task-06-windows-wechat-compatibility-profile` 的 phase-2 产物及其直接代码路径。未修改业务代码。

## 1. 设计与架构

- `ActiveWindow` 未被扩展；新增的 HWND、PID、路径、哈希和 ROI 均留在 `pub(crate)` Rust 类型中，未发现新增 Tauri command、event 或配置持久化路径。
- 嵌入式 catalog、私有 identity 和重读比较的分层符合本步骤“不采集、不 OCR、不调用模型”的边界。
- **P1 — 实际 Windows 读取路径无法满足主题准入，启用 profile 后仍永久拒绝。** `monitor.rs:1324-1326` 明确把 `ForegroundWindowEvidence.theme` 固定为 `None`；`window_identity.rs:144-147` 遇到 `None` 立即返回不匹配。`validate_foreground_wechat()` 调用的正是该 Windows 读取函数（`runtime.rs:10-17`）。因此即使路径、SHA-256、版本、DPI、拓扑和窗口尺寸均正确，结果仍是 `WX_PROFILE_UNSUPPORTED`，与变更记录中“精确匹配时生成内部 identity”的目标不一致。

  修改指南：在启用首条 production profile 前，实现一个不依赖标题/appName 推断的直接主题观测，并将其与 probe 的 theme 定义和 Windows UAT 绑定；或者明确把主题取证及 identity 可用性移到后续步骤，保持 catalog 为空且不要宣称本步骤已具备可匹配 profile。增加一条经真实 `read_foreground_window_evidence()` 接线的 Windows 测试，分别覆盖 light/dark 和未知主题拒绝。

- **P2 — 重读 API 未强制重读真实前台窗口。** `revalidate_foreground_wechat()` 接收调用方传入的 `ForegroundWindowEvidence`（`runtime.rs:28-35`），只比较该值（`window_identity.rs:118-141`），自身不调用 `read_foreground_window_evidence()`。后续 capture 调用者可以错误地复用第一次读取的 evidence，规避“使用前必须重读”的 API 约束；目前没有调用点或集成测试能证明实际重读。

  修改指南：Windows 版本的 revalidate 门面应在内部重新读取前台证据并完成比较，或将纯比较函数限制为测试/更低层实现细节，避免后续调用者能够传入旧快照。补充“切窗、最小化、移动/缩放、DPI 改变”时真实重读返回 `WX_NOT_FOREGROUND` 或 `WX_REQUEST_STALE` 的 Windows 测试。

## 2. 可读性与可维护性

- 模块命名、ROI 边界检查和路径大小写归一化清晰；`WindowInstanceToken` 与 `WechatWindowIdentity` 没有 `Serialize`/`Deserialize` 派生。
- **P2 — catalog 版本化没有实际 allowlist。** `CompatibilityCatalog::parse()` 只要求 `catalog_version` 非空（`profiles.rs:61-77`），`profile_version` 也只要求非空（`profiles.rs:164-168`）；与方案“仅支持已知 schema/catalog/profile version”的约束不符。任意新字符串版本会被接受，而 `enabled_profiles()` 实际返回所有已解析条目（`profiles.rs:80-82`）。

  修改指南：把支持的 catalog/profile 版本表示为明确常量或枚举，并对未知版本返回 `InvalidCatalog`；添加未知 catalog 版本、未知 profile 版本和混合版本的测试。

- **P2 — `enabled: false` 不能作为禁用条目保留。** schema 中有 `enabled` 字段，但 `TryFrom<RawProfile>` 在该值为 false 时拒绝整个 catalog（`profiles.rs:164-166`）。这与方案的“已发布错误 profile 可置为 disabled”不一致；将来 catalog 同时含启用和禁用条目时会整体失效，而非仅跳过禁用项。

  修改指南：解析时保留已验证的 disabled profile，`enabled_profiles()` 仅筛选 enabled 条目；无效条目仍应令 catalog fail-closed。补充 enabled/disabled 混合 catalog 的回归测试。
