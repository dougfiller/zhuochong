## 3. 发现

### [P1] 启动留存清理会跟随 content 根目录符号链接，可能递归删除微信目录之外的 UUID 目录

- 位置：`desktop/src-tauri/src/wechat/content.rs:112-133`，调用点 `desktop/src-tauri/src/main.rs:4213-4231`。
- 证据：`cleanup_expired` 仅以 `self.root.exists()` 判断根目录，随后直接 `read_dir(&self.root)` 和 `remove_dir_all(path)`；不像 `delete_all`（`content.rs:80-107`）那样先以 `symlink_metadata` 拒绝符号链接根目录。若 `wechat_reply/content` 被替换为指向其他位置的符号链接，启动时会枚举该目标，并删除名称恰为 UUID 且修改时间过期的子目录。
- 影响：这违背方案第 5.1 节“只删除微信 content 根、永不跟随越界路径或符号链接”的边界。因为清理在应用启动时自动运行，只要留存开关开启，就存在跨根目录破坏性删除风险。
- 测试缺口：现有 `wechat::content::tests` 仅验证 `delete_all` 的普通 UUID/非 UUID 条目；未覆盖 `cleanup_expired` 的根目录符号链接、子目录符号链接、越界目标和时间边界。

### [P1] `WechatContentStore::retain` 未接入 runtime，也未受 lease、阶段与配置快照约束；可选正文留存并未实现为方案承诺的受限流程

- 位置：`desktop/src-tauri/src/wechat/content.rs:46-76`、`desktop/src-tauri/src/wechat/runtime.rs:57-238`。
- 证据：全文调用搜索显示生产代码只在 command 和启动清理处构造 `WechatContentStore`；`retain` 只在自身测试中调用。`WechatReplyRuntime` 没有 `WechatContentStore`、留存配置快照或正文留存方法，也没有在取消、失效或配置中途关闭时清理该 request 已写内容。`retain` 仅接收任意 `RequestId`、`kind`、`&[u8]` 和布尔/天数参数，无法核验活跃 lease、合法阶段或正文来源。
- 影响：实现日志所述“显式开启时写入受限正文”“关闭后停止并删除本 request 已写内容”没有可执行的生产路径。未来任何 crate 内调用方也可用任意 UUID/字节调用 `retain`，绕过 single-flight、取消、阶段和可信正文类型边界。
- 测试缺口：没有启用留存后的 runtime 集成测试，未覆盖 request 取消、过期 lease、阶段不符、配置从开到关、已写正文清除、四类固定正文对象或错误持久化 fail-closed。

### [P1] Trace 的可持久化 M2 metadata 未做白名单/长度/枚举校验，不能证明 metadata-only 边界

- 位置：`desktop/src-tauri/src/wechat/trace.rs:17-28`、`293-297` 与 `desktop/src-tauri/src/wechat/runtime.rs:86-156`。
- 证据：`M2TraceMetadata` 的 `query_hmac`、`active_import_snapshot_hash`、`index_generation_id`、`retrieval_mode`、`hit_ids` 和 `model_request_id` 均为不受限制的 `String`/`Vec<String>`。`validate_event` 只校验 schema 版本、非零 `stage_seq` 与 request UUID，不校验事件 ID、阶段/状态/终态组合、M2 字段的格式/数量/长度，或 `retrieval_mode` 是否为冻结枚举。`complete_retrieval` 直接接受并写入该结构。
- 影响：任一 crate 内未来接线可把 OCR、建议、路径或原始错误等任意长字符串装入允许字段后持久化，并由 `list_wechat_reply_traces` 返回。这样无法满足方案所要求的“trace 绝不含正文/路径”和 M2 字段受限的审计格式。
- 测试缺口：fixture 与单测只覆盖正常行、分页和尾损坏；没有正文样式字符串、超长字段、未知 retrieval mode、过多 hit、非 UUID event ID 或非法 stage/status 的拒绝用例。

### [P2] 非法阶段请求只返回错误而不写失败终态或释放 slot，未满足既定的 fail-closed 终止语义

- 位置：`desktop/src-tauri/src/wechat/runtime.rs:101-115`、`127-151`。
- 证据：`transition` 的 expected state 不匹配、`ReplyReady` 前模型计数不等于 1、或 `candidate.advance` 失败时直接返回 `WX_CONTRACT_VIOLATION`，既不调用 `transition_terminal`，也不释放 active slot。`complete_retrieval` 的 `candidate.complete_retrieval` 失败也同样直接返回。只有调用方随后显式取消才能继续释放 slot。
- 影响：错误回调可留下没有终态 trace 的 active request；后续请求会持续得到 `WX_BUSY`。这与方案第 3.1/6 节中“非法 stage/request/seq 终止当前 request、记录终态”的约束不一致。
- 测试缺口：`cancelled_lease_cannot_progress` 仅测试手动取消后继续 transition 的返回值；没有断言非法 expected state、M2 request 不匹配或模型计数错误会留下 terminal trace 并允许下一请求开始。

## 4. 修改指南（不在本审查中实施）

1. 为 `WechatContentStore` 提取统一的受管理根目录检查：对根与候选 request 目录使用 `symlink_metadata`、canonical/boundary 检查；`retain`、`delete_all`、`cleanup_expired` 均复用它。遇到根/子项符号链接或异常条目时 fail-closed、保留条目并计数，不执行递归删除。补充临时目录下的根符号链接、子符号链接、过期 UUID、非 UUID 与边界时间测试。
2. 将正文持久化收口到 runtime 的私有、lease 持有 API：每次写前重读/获取最小配置快照，核验 active request、阶段、取消/超时和固定正文对象类型；配置关闭、取消或失效时删除该 request 已写正文。不要公开接收任意 UUID 与裸字节的持久化入口。
3. 将 trace 事件和 M2 metadata 改为严格构造器或私有字段；限制每个字符串长度/字符集、hit 数量和 score 范围，`retrieval_mode` 用枚举，逐项拒绝正文、路径与未知状态。扩展 `validate_event` 以校验 event UUID、stage/status/finalState/errorCode 的合法组合，再为每个拒绝分支添加反例。
4. 在 runtime 的非法 expected state、非法 M2 retrieval 和模型调用计数错误分支中，以可追踪的 `Failed` 终态 fail-closed；若终态 trace 也无法写入，清空 slot 并返回固定 trace 持久化错误。补充“错误后下一请求不再 `WX_BUSY`”和终态 sequence 断言。
5. 修复后重跑本报告第 5 节命令，并新增上述 Rust 集成/反例测试。Windows 微信、OCR、检索与模型实机流程仍应保持 `not-run`，不能由 macOS 合成测试替代。
