## 审查发现

### P1：未验证的 `source_id` 被原样写入产品 SQLite，可能持久化私有源路径

- 证据：`desktop/src-tauri/src/knowledge/runtime.rs:11-17` 将任意调用方提供的 `source_id` 直接传给 importer；`desktop/src-tauri/src/knowledge/archive_importer.rs:195-198,279-289` 继续传递；`desktop/src-tauri/src/knowledge/archive_store.rs:62,173-203,223-245` 将其作为 `archive_imports.source_id` 入库。
- 风险：接口既未限制该值为匿名标识，也未哈希或拒绝路径。未来显式导入入口若将用户选择的目录传入该参数，会在 `data_dir/wechat_knowledge/knowledge.sqlite` 长期保存用户绝对路径，违反本变更记录所述“源路径不离开方法、只记录匿名 metadata”的边界。
- 修改指南：删除持久化的自由文本 `source_id`，或在 importer 内部从已允许的匿名 fingerprint 导出不可逆审计 token；若保留调用方参数，必须拒绝路径分隔符、绝对路径/URI 和其他非限定匿名格式。补充测试，传入 `/Users/example/archive` 后查询派生库，断言其中不存在该原文或路径片段。

### P1：manifest 的来源、范围枚举及媒体选项只解析未执行白名单校验

- 证据：`desktop/src-tauri/src/knowledge/archive_schema.rs:41-51` 仅把非 `selected`、非满足 `full` 条件的任意 `scope.kind` 归为 `Filtered`；`source.kind`（67-69）和 `options.include_media`（118-121）没有被任何导入路径读取。实际 `cargo test` 也报告这些字段 `never read`。`desktop/src-tauri/src/knowledge/archive_importer.rs:199-212` 在 schema version 校验后继续导入，未校验上述值。
- 风险：如 `source.kind` 是未知来源、`scope.kind` 为未来/拼写错误值或 `includeMedia: true`，当前代码仍会接受 manifest；后者虽暂未打开媒体，但不符合“仅 JSON、媒体请求 fail-closed、未知结构不猜测”的冻结契约，也会让未来接线误以为已获准导入媒体。
- 修改指南：在 `route_manifest` 或独立的 `validate_v1_contract` 中精确允许 `source.kind == "user_selected"`、`scope.kind in {"selected", "full"}`，并要求 `includeMedia == false`；任一不符均返回 `KB_SOURCE_UNSUPPORTED`。为三类非法 manifest 分别补负向 Rust 单测，并让静态门禁验证这些测试名称或行为，而非仅检索字段名。

### P2：流式 visitor 仍会为单条消息完整分配正文/媒体字符串，未满足大输入的内存上界

- 证据：`desktop/src-tauri/src/knowledge/archive_importer.rs:381-391` 将 `text` 和 `media` 反序列化为 `Option<String>`；`575-576` 对每个元素调用该反序列化。随后 420-426 才丢弃字符串。测试只证明未将整个 messages 数组反序列化为 `Vec<MessageV1>`，没有构造超长单条正文或媒体字段。
- 风险：攻击者/异常导出可在一条 JSON message 中放入极大的 `text` 或 `media` 值，导致导入时分配该值的全部内存；因此 151 MiB 级消息文件的“流式内存”验收不能由当前微型 fixture 推导出来。
- 修改指南：使用不会保存正文的 serde visitor/受限字符串反序列化，或在分配前以严格字节上限拒绝正文和 media token；增加至少一个超限单 message fixture（可程序生成到临时目录），断言返回 `KB_SOURCE_UNSUPPORTED` 且不创建/写入导入记录。受控 151 MiB / 108,447 条样本的运行结果仍应单独记录，不能用小 fixture 替代。

### P2：符号链接检查存在检查与打开之间的竞态窗口

- 证据：`desktop/src-tauri/src/knowledge/archive_importer.rs:101-108` 先用 `symlink_metadata` 检查普通文件，随后以会跟随符号链接的 `File::open` 打开相同路径；`124-140` 的 member audit 也按路径再次检查。测试 `621-626` 只验证稳定路径输入被拒绝，并未覆盖检查后替换为符号链接的场景。
- 风险：源目录若在导入期间被其他进程替换文件，检查后的 `File::open` 可能跟随新符号链接，突破“符号链接 fail-closed / 仅 manifest 声明成员”的读取边界。
- 修改指南：在目标平台使用不跟随链接的打开语义（例如 Unix `O_NOFOLLOW`，Windows 对 reparse point 使用等价句柄校验），并在取得句柄后验证文件类型/身份；若不能提供跨平台无竞态保证，应明确限制受信任的不可变目录并阻断不满足条件的来源。补充可控替换或抽象文件系统测试，证明替换后拒绝且不会读到目标文件。
