## 1. 改动目标

- 为 `messages[]` 的既有 `DeserializeSeed` 流式消费补充确定性规范化、源序号、canonical hash 和 generation 内 identity 去重。
- 将媒体声明写为独立的多行元数据，固定 `exists_state='unknown'`，不读取、遍历、探测或复制媒体正文。
- 导入完成只产生 `ready_candidate`，不在 archive importer 中创建索引或激活 catalog。

## 2. 改动范围

- 修改：`desktop/src-tauri/src/knowledge/archive_importer.rs`、`store.rs`、`migrations.rs`。
- 新增：`migrations/knowledge/0003_streaming_message_normalization_media.sql` 与静态门禁 `kaifa/kaifa_test/verify_streaming_message_import.py`。
- 补录：`kaifa/kaifa_personnel/mingling.md`、`kaifa/kaifa_test/test.md`。
- 未改：微信采集/OCR/输入发送、Tauri command、前端、模型、网络、真实导出或媒体文件。

## 3. 详细改动

1. schema head 升至 3；新增 message normalization、media ordinal/类型/存在状态/元数据和 import-generation input key 表。
2. `MessageV1` 增加严格白名单字段：可选 stable ID、render type、reference、extra 与 `mediaRefs`；文本和字段长度、RFC3339、kind/render 白名单、相对媒体路径及 extra 白名单均 fail-closed。
3. 每条流式消息按源 ordinal 规范化；缺失 stable ID 时用 account/conversation/sender/time/kind/text hash/ordinal 计算 fallback key；canonical hash 覆盖元数据和媒体声明。
4. Store 在每个至多 256 条的 batch transaction 内先写 generation input key，重复 identity 使该 batch 回滚；随后写 immutable version、normalization、source provenance、ordinal media rows 和 membership。
5. 删除 importer 内的自动 index/register/activate 路径，保持 candidate 不可见直到后续明确发布步骤。
6. 继续收敛阻断：不再保存已完成 staging/candidate 集合。单会话 meta、JSON、批写入或计数失败会清理该会话、递增失败计数并继续后续会话；若至少一个会话成功，source 记为 `incomplete`，不激活 catalog。
7. 最终收敛：manifest 改为固定大小 header 加 `DeserializeSeed` cursor，预检、会话导入和 member audit 分三次逐项扫描；不再反序列化会话清单。member audit 改为 count + SHA-256 digest，并在末尾流式写入后以一个 Store transaction 将全部成功 staging 原子转为 `ready_candidate`。
