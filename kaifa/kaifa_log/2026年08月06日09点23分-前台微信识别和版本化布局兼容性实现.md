## 1. 改动目标

- 以嵌入式、严格 schema 校验的 catalog 替换“非空 signature material 即可信”的占位判断。
- 仅在前台实例、可执行文件、窗口/DPI、Windows build、显示器拓扑、主题和 ROI 精确匹配时生成不序列化的内部 identity。
- 没有 Windows 实机探针证据时保持空 catalog，所有请求 fail-closed，绝不截图、OCR 或调用模型。

## 2. 改动背景与基准

步骤 5 的 `wechat-windows-v1` 是准备中的占位 catalog，并不具备身份强度。本次沿用步骤 4 已冻结的 `WX_NOT_FOREGROUND`、`WX_PROFILE_UNSUPPORTED`、`WX_WINDOW_UNSUPPORTED` 与 `WX_REQUEST_STALE` wire 契约，仅扩展步骤 6 所需后端门禁。

## 3. 改动范围

### 3.1 涉及范围

- `monitor.rs` 新增 Windows 私有证据读取：HWND/PID/启动时间、路径/文件名/SHA-256/ProductVersion、bounds、DPI、Windows build 与显示器角色；`ActiveWindow` 不变。
- 新增严格 catalog/ROI/schema 解析、私有 identity 和二次读取 stale 比较。
- 设置选项仅显示验证后的 enabled profile；当前列表为空。
- 新增静态检测程序、Rust 单元测试、命令与测试记录。

### 3.2 不涉及范围

- 不实现截图、覆盖层、OCR、RAG、模型、数据库、协议、UI Automation、键鼠输入、粘贴或自动发送。
- 不修改 Svelte 设置页、配置保存结构、普通 Work Review 前台统计或浏览器 URL 路径。

## 5. 处理流程或行为变化

```text
前台窗口重读 -> PID/最小化/bounds/DPI/exe 证据
  -> catalog 精确匹配
  -> 0 个或多个匹配：WX_PROFILE_UNSUPPORTED
  -> 1 个匹配：仅返回 Rust 内部 identity
  -> 使用前重读，instance/PID/bounds/DPI/profile 改变：WX_REQUEST_STALE
```

当前 catalog 没有 enabled profile，故稳定止于拒绝分支，不进入 capture。

## 6. 输入、输出与接口变化

- 现有 catalog option wire 形状不变；无探针时选项为空且任何保存的 ID 都不可信。

## 7. 文件与目录变更

## 8. 关键设计决策

### 8.1 空 catalog 而非猜测 profile

目标 Windows 的版本、路径、文件哈希、ProductVersion、DPI、拓扑、主题和 ROI 都未获实机证据。填入示例值会构成错误放行，因此 `profiles` 为空。

### 8.2 不扩展 ActiveWindow

普通 Work Review 的公开 DTO 和消费者保持不变，敏感证据仅在后端私有类型中流动。

### 8.3 二次读取优先于复用

后续倒计时/capture 阶段必须重读；窗口实例、PID、bounds、DPI 或 profile 改变使旧 identity 失效。
