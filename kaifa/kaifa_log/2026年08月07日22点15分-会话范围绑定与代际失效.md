- 为 M2 增加默认拒绝、仅进程内的显式知识会话绑定，启动始终为新 nonce、`unbound`、generation 0。

### 2.2 本次基于的版本或状态

基于 `main` 的 `5f9ca7a` 及当前工作区中步骤 24 的方案工件实现。保留步骤 23 调度状态、`kaifa/定时任务.md` 和其他 LOOF 工件的既有并行 dirty 改动，未将其纳入本阶段实现。

### 2.3 改动原因

原 scope 不能区分跨 account 同值会话，也没有将用户选择绑定到当前前台窗口/header、active catalog 与单调代际；重建、窗口切换或晚到结果存在误用旧授权的风险。

## 8. 关键设计决策

### 8.1 Store 仍是唯一 SQL owner

会话目录、opaque key 计算和 active 解析全部留在 `KnowledgeStore`，binding 只持进程内快照，不缓存 SQLite row id 或连接，避免第二套授权事实源。

### 8.2 opaque key 同时包含 account 与 conversation

采用带域分隔符的 SHA-256 确定编码，跨内部 row id 重建稳定；跨 account 同 conversation stable id 不碰撞。key 不是权限 token，每请求仍重验 active mapping/denial/catalog。

### 8.3 header 是用户确认的复核线索，不是联系人识别

只复用现有 header ROI 与内存 OCR，不比较 displayName、不使用通用窗口标题。空白、通用、数字/标点或多段结果进入 unreliable，每请求必须再消费一次性确认。

### 8.4 mutation 与外部补偿分离

binding mutex 内只生成纯 `BindingMutation`；释放锁后固定推进 capture counter、取消匹配 M2 lease、取出并清除精确旧建议。M1 无 binding generation，不被误清。
