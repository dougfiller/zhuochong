## 1. 改动目标

- 将 `knowledge.sqlite` 升级至 schema v2，持久化导出时间、coverage 类型、版本 content hash 约束和 lineage 查询索引。
- 将 JSON archive 的文本消息以 256 条 batch 写入 staging generation；正文版本只追加，相同消息与正文复用既有 version。
- 只有所有会话 candidate 与共享 ready index 都就绪后才在一个事务中激活；失败候选不能替换旧 active catalog。

## 3. 关键行为

1. manifest 的 `exportedAt` 必须严格 RFC3339 解析；当前 v1 仍只接受 `full`/`selected`，没有明确 incremental 声明时拒绝而不猜测。
2. 导入器只从 allow-list JSON 流式读取；文本正文规范化后由 Store 计算 content hash，原始导出路径不进入数据库。
3. 同一 message identity + content hash 只保留一个 version；正文变化追加 version，generation membership 指向本次胜出的 version。
4. selected/filtered candidate 从其 parent active generation 复制范围外 membership，并标记 `retained_outside_coverage`；full candidate 不复制。
5. candidate、index、parent 关系任一不就绪时 activation 回滚，`read_active_snapshot` 只读取 ready active index。

## 5. 当前边界与风险

- 当前 `wechat_archive_v1` 没有白名单的 incremental/base 字段，因此 incremental 包仍 fail-closed；没有以目录、消息数或时间推断增量。
- 现有 schema v1 若已有 source 缺少无法安全回填的 v2 source facts，Store 会保持 unavailable，而不会覆盖本地库。
- 本步骤未实现 embedding、chunk 或真实 `knowledge_retrieve()`。
