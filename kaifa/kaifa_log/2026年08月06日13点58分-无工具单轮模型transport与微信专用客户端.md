## 1. 改动目标

- 从 `commands/ask.rs` 抽取四类 provider 共用的无工具、非流式、单轮文本 transport。
- 增加不暴露 Tauri command 的微信私有 model client，只接受 M1/M2 已验证领域类型和精确成功的文本模型 profile。
- 让 runtime 只在已记录一次 transport 且 lease/代际仍匹配时提交 `ReplyReady`。

## 2. 改动背景与基准

步骤 4 已固定 M1/M2 类型和 M2 先检索契约；步骤 9 已提供 single-flight runtime 与一次 transport 计数。本次未添加用户触发入口、自动监听、截图/OCR、知识检索、数据库、上传、剪贴板或发送能力。

## 5. 处理流程或行为变化

```text
普通单轮 command -> SingleTurnTextTransport -> provider 直接单请求
已验证微信 profile + M1/M2 可信输入 -> WechatReplyModelClient -> SingleTurnTextTransport
runtime 已记录一次 transport + 当前 lease/代际 -> complete_generated_reply -> ReplyReady
```

无效 profile 在 transport 前返回 `WX_TEXT_MODEL_UNAVAILABLE`；模型错误、工具调用、截断或空白结果返回 `LLM_FAILED`，不保留部分回复。

## 6. 输入、输出与接口变化

- 新内部 transport 仅接收 system prompt 与一条 user prompt，不接收 history、tools、tool-result、stream 或 Agent 参数。
- 微信 client 只接收 `M1ReplyInput` 或 `ModelKnowledgeContext`；没有前端 config、裸 OCR/检索列表或 Tauri API。
- `generate_text_answer_with_model` 外部签名保持不变。

## 8. 关键设计决策

### 8.1 复用 provider parser 与共享 HTTP client

保留现有 endpoint、认证头和超时配置，避免在微信路径新建 client；单轮路径直接发送，确保一个逻辑请求不会触发 retry。

### 8.2 微信没有模型 fallback

只接受用户选择且验证成功的精确 profile。缺失、未知、未测或空模型均 fail-closed，不能改选普通聊天模型或首个 profile。

### 8.3 不新增生成入口

本步骤只提供私有契约与 runtime 提交能力，未注册 command 或接入 UI，因此不产生自动回复、复制、粘贴或发送行为。
