## 1. 改动目标

- 为步骤 4 的纯领域契约补上微信/知识库的安全空 runtime、配置、设置页与 DTO command。
- 所有路径保持 `not_ready`：不采集、不 OCR、不调用模型、不导入/索引/检索、不写 `knowledge.sqlite`，也不发送微信消息。

## 2. 改动背景与基准

### 2.1 改动前状态

`wechat/`、`knowledge/` 已有步骤 4 的类型和状态机，但没有 managed state、设置页或步骤 5 的安全配置。

### 2.2 本次基于的版本或状态

### 2.3 改动原因

让后续受控功能有明确的 fail-closed 配置和 UI 落点，同时不把尚未交付的微信回复或 M2 检索伪装成可用功能。

## 3. 改动范围

### 3.1 涉及范围

- `desktop/crates/core/src/config.rs`：新增 `wechat`/`knowledge` 配置 DTO、默认值和归一化。
- `desktop/src-tauri/src/wechat/`、`knowledge/`：新增 catalog/validator、空 runtime、只返回安全 DTO 的 command。
- `desktop/src-tauri/src/main.rs`、`commands/mod.rs`：注册三个独立 state 与三个 command。
- `desktop/src/routes/settings/`、四语 locale：增加微信和知识库的“准备中”设置页。

### 3.2 不涉及范围

- 不接入微信窗口、截图、OCR、剪贴板、键鼠、UI Automation、协议/数据库读取、自动粘贴或发送。
- 不接入模型传输、M1/M2 编排、导入、embedding、检索、MCP、Bot、Agent、联网或上传。

### 3.3 影响对象

## 5. 处理流程或行为变化

```text
Settings → AppConfig.wechat / AppConfig.knowledge → normalize → existing atomic save + .bak recovery
Settings → safe status command → independent empty runtime/store → stable not_ready error code
```

所有 command 仅短暂复制 `AppConfig` 快照；不会序列化 `AppState`、数据库、聊天正文、命中、密钥、allowlist、ROI 或句柄。

## 8. 关键设计决策

### 8.1 配置只保存选择，不保存兼容性材料

微信配置只保存 trusted profile ID；catalog 内部持有版本和验证材料，前端没有 appName、ROI、可执行路径或签名编辑入口。

### 8.2 知识库只接受独立 loopback embedding

只允许 `ollama_loopback` 配合精确的 `http://localhost`、`http://127.0.0.1` 或 `http://[::1]` 地址；拒绝 DNS、LAN、`0.0.0.0` 与 https，不复用 Work Review 的 `embedding_*` 或语义记忆配置。

### 8.3 空实现保持不可用

三项 managed state 没有 `AppState`、DB、文本、截图、模型 client 或自动化器；未来慢任务须在锁外执行，但本步骤不调度任何慢任务。
