## 1. 改动目标

- 用同一 opaque requestId 串联 retrieval stageSeq=5、binding/context/model permit、loopback embedding 和真实 physical model attempts。
- 让审计只表达固定元数据与能力计数，无法表达聊天/OCR/hit/回复正文、凭据、provider body、endpoint、路径或内部 source IDs。
- 增加不可 default-pass 的 M2 strict gate；缺 Windows、candidate、真实模型、package、素材授权或任一必需矩阵行时只能 blocked/fail。

## 2. 改动背景与基准

### 2.1 改动前状态

步骤 25 已有强制检索、`ModelCallPermit`、`FrozenRagTransportEnvelope` 和两次有限重试，但 physical attempt 只在 fake transport 中可见；embedding audit 无 request correlation，也没有 M2 strict after-gate。

### 2.2 本次基于的版本或状态

基于 `main@e25e6c3` 与步骤 25 未提交并行工作区。开始前步骤 25 的 LOOF state、调度器文件和本方案文档已 dirty；这些文件均保留且不归为本 run 代码修改。

### 2.3 改动原因

不能用时间戳、logical model counter、日志字符串或历史 M1 default-pass 证明“先检索后模型”和禁止能力零调用，需要真实 transport 最后一层 spy、固定 schema 与严格证据 join。

## 4. 详细改动清单

- `observability.rs`：封闭 event/capability/origin/outcome 枚举、`deny_unknown_fields`、16 KiB JSONL、持久化 sink、spy 和固定 capability snapshot。
- `model_client.rs`：在 `SingleTurnRagTransport` 调真实 provider 前记录 physical attempt；audit 错误与 provider 错误分型，audit 失败不重试且 transport=0。

- `embedding.rs`、`retrieve.rs`：requestId 显式关联 metadata/query HTTP attempt；不使用 thread-local；旧无 audit Store API 保留。
- `verify_m2_observability_gate.py`：固定 45 fault IDs、44 AC IDs、能力 key、事件字段、join/attempt/hash/零计数/strict verdict 与源码能力边界。
- `work-review-m2-after-gate.*`：完整但诚实 blocked 的发布证据占位；没有 default-pass/waiver。
- `desktop/.github/workflows/ci.yml`：加入正反 strict fixture 与 M2 微信回归。

## 5. 处理流程或行为变化

```text
knowledge_retrieve(requestId + explicit audit sink)
  -> embedding metadata/query physical HTTP event
  -> trace append Generating(stageSeq=5)
  -> retrieval_completed(same permit metadata)
  -> authorize_model_call
  -> model_transport_started(attempt=1[,2], frozen bytes SHA-256)
  -> exact SingleTurnTextTransport
```

审计写失败发生在模型前时立即返回 `WX_AUDIT_PERSIST_FAILED`，不调用 provider；provider retryable 错误仍只允许同 envelope 的第二次 attempt。

## 6. 输入、输出与接口变化

- 新增内部 `M2AuditSink::record(M2AuditEvent) -> Result<(), ContractError>`，不暴露到 command/UI。
- `KnowledgeStore` 保留原 `knowledge_retrieve(request)`，新增 crate 内 `knowledge_retrieve_with_audit(request, Option<&M2AuditSink>)`。
- `KnowledgeError`/`ContractError` 增加稳定 wire code `WX_AUDIT_PERSIST_FAILED`。
- strict gate exit code：`0=pass`、`1=fail`、`2=blocked`。

## 8. 关键设计决策

### 8.1 在最后一层 transport 前记录

调用方“将要调用”的日志不能证明真实 physical attempt。事件由持有 `RagTransportAttempt` 的 `SingleTurnRagTransport` 写入，再调用 exact frozen request。

### 8.2 strict gate 与阶段实现完成分离

自动化可完成，但发布 gate 仍因真实环境/安装包/授权缺失而 blocked。M1 的历史授权默认政策不得传播到 M2。

### 8.3 显式 correlation 而非 thread-local

requestId 随 `KnowledgeRetrieveRequest` 和 sink 显式传递，并发 request 不依赖线程亲和或全局 FIFO。
