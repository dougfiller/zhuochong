## 1. 改动目标

- 抽出单一 f32-LE、L2 归一化、流式余弦 Top-K 和 RRF primitive，保留屏幕语义记忆原 API 与旧 BLOB 宽容语义。
- 为聊天知识实现独立、无 API key 的 Ollama loopback embedding 路径，固定 no-proxy、no-redirect、单次 DNS 解析与连接地址 pin。
- 复用步骤 20 frozen building/active generation 和 `knowledge_chunks.embedding`，严格验证 dimension、finite、content hash 与 NULL 续作。
- 本步骤不激活 generation、不接入最终 `knowledge_retrieve()`/模型 transport、不改变微信输入发送边界。

## 2. 改动背景与基准

### 2.1 改动前状态

屏幕语义记忆的向量编解码、Top-K 和 RRF 分散在 database/command；聊天知识只有 frozen generation、chunk/FTS 和基础 loopback 字符串校验，尚无严格向量读写与 pinned HTTP client。

### 2.2 本次基于的版本或状态

基于 `main` / `fa5d8e9` 及步骤 20 schema v4、stable `chunk_key`、building generation 产物；没有修改 migration。

### 2.3 改动原因

聊天正文不能继承屏幕记忆的云 endpoint/API key/FTS fallback；知识向量又需要与屏幕功能共享纯算法，避免两份 RRF/向量实现漂移。

## 3. 改动范围

### 3.1 涉及范围

- core 共享 semantic primitive 与屏幕 database wrapper。
- Tauri 共享 embedding wire payload/parser、屏幕 command wrapper。
- knowledge 专用 endpoint/resolver/client/build/query orchestration 与 Store 严格向量 API。
- Rust/HTTP/SQLite 测试、静态门禁、命令清单与测试说明。

### 3.2 不涉及范围

- 未修改 migration、catalog 激活、最终 M2 检索编排、设置 UI、微信 capture/OCR/input/clipboard/send、agent/bot/search/upload。

### 3.3 影响对象

- 屏幕语义记忆继续兼容 OpenAI batch、Ollama legacy、API key 与 embedding 失败时 FTS 降级。
- 聊天知识仅允许精确 loopback HTTP Ollama wire contract，并在配置、HTTP、fingerprint、dimension、BLOB 或 generation 异常时失败关闭。

## 5. 处理流程或行为变化

```text
building frozen config
  -> validate endpoint -> resolve once -> pin loopback -> /api/tags fingerprint
  -> pending embedding IS NULL (<=32) -> /api/embed -> strict normalize/encode
  -> transactional chunk_key + content_hash write -> remain building

active ready config
  -> pinned fingerprint + query embedding
  -> exact BLOB vector scan + FTS -> shared RRF(chunk_key)
  -> catalog generation recheck -> hybrid hits or fail-closed
```

## 8. 关键设计决策

### 8.1 算法共享、领域错误策略分离

core 只有一份算法；屏幕 wrapper 继续跳过旧维度块，知识 wrapper 对 NULL/尾字节/维度/NaN/Inf 整次失败。

### 8.2 专用 client 固定网络约束

聊天 client 不接受 header/key 参数，固定 `.no_proxy()`、redirect none、5 秒建连和 60 秒请求；`localhost` 只解析一次并把地址集合 pin 给 reqwest。

### 8.3 不在步骤 21 激活或接入模型

向量 build 完成后仍保持 building，active 只读 ready catalog；最终激活与 M2 `RetrievedReply` 编排留给步骤 22/23。
