## 1. 改动目标

- 在 `<AppState.data_dir>/wechat_knowledge/knowledge.sqlite` 建立独立、版本化的知识库。
- 让 `KnowledgeStore` 成为唯一 SQLite/迁移/SQL 所有者，导入器仅传递脱敏 DTO。
- 保持未就绪知识库的 `KB_NOT_READY` fail-closed 行为，不改 Work Review 数据库、M1、前台微信或 UI。

## 2. 改动背景与基准

### 2.1 改动前状态

知识库导入器直接创建 `WechatArchiveStore`，并在该对象内连接 SQLite、执行临时 `archive_*` DDL；受管理的 `KnowledgeStore` 只是空门面。

### 2.2 本次基于的状态

基于本 run 的阶段 1 方案：`kaifa/kaifa_plan/2026年08月06日20点57分-建立独立knowledge.sqlite版本化migration和单一Store.md`。

### 2.3 改动原因

临时审计表和多连接所有者无法保证 schema 可演进、候选代际不可见与数据库异常 fail-closed，因此迁移为单一 Store 和迁移清单。

## 3. 改动范围

### 3.1 涉及范围

- 新增 `knowledge/migrations.rs`、`knowledge/migrations/knowledge/0001_initial.sql`、`knowledge/store.rs`。
- 收缩 `archive_store.rs` 为 archive DTO/hash 工具；`archive_importer.rs` 改为依赖 `&KnowledgeStore`。
- 启动时以已有 `data_dir` 创建 `KnowledgeStore::open_or_unavailable` 并 managed；失败不阻止现有应用启动。
- 新增静态门禁 `kaifa/kaifa_test/verify_knowledge_store.py`，并补录测试与命令说明。

### 3.2 不涉及范围

- 不修改 `desktop/crates/core/src/database.rs::Database::init_tables()` 或 `workreview.db`。
- 不实现真实消息正文写入、chunk、向量、检索、lineage 合并、前端或微信采集。
- 不把 M2 降级到 M1 或裸模型。

### 3.3 影响对象

- 后续 archive/chunker/indexer/retriever 只能使用类型化 Store API；不能持有 `rusqlite::Connection`。
- 知识库打开、schema、忙锁或损坏失败时，知识操作返回 `KB_NOT_READY`，现有 M1/Work Review 继续独立运行。

## 5. 处理流程或行为变化

`data_dir → KnowledgeStore::open_or_unavailable → writer: migration/PRAGMA/FTS5 校验 → typed staging/candidate → 原子 activate catalog → bounded read-only active snapshot`。

导入器的流程变为：`只读 archive guard → DTO/member audit → KnowledgeStore`。它不再拥有数据库路径、连接或 SQL。

## 6. 输入、输出与接口变化

- `KnowledgeStore` 提供 `begin_staging_source`、`append_staging_batch`、`mark_ready_candidate`、`read_active_snapshot`、`activate_candidate`、`deny_or_delete` 等内部类型化 API。
- active 读取只接受已 ready 的 catalog index；staging、ready_candidate、失败代际和存在 denial 的状态均返回 `KB_NOT_READY`。
- archive import 返回既有 `ArchiveImportSummary`；源路径和消息正文不进入数据库。

## 8. 关键设计决策

### 8.1 失败时保留已有库

未来版本、非法 schema、外键错误、FTS5 不可用和损坏库全部映射为 `KB_NOT_READY`；不删除、覆盖或重建用户库。

### 8.2 候选与 active 分离

候选 import/index 必须通过单一 writer transaction 更新会话指针和 catalog，读者只看 ready active index。

### 8.3 reader 使用只读连接

reader 打开后设置 `query_only=ON`，有固定上限；FTS5/schema/外键设置被检查。完整 `integrity_check` 在 writer 打开时执行，因为 SQLite 对 FTS5 的完整性验证在只读连接上会尝试写入内部状态。
