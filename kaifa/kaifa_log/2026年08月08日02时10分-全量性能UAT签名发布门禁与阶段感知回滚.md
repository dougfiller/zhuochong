- 建立只接受同批真实证据的 final M2 strict gate，固定 `0=pass/1=fail/2=blocked`，并从 raw sample 重算性能聚合。

## 5. 处理流程或行为变化

```text
native picker roots
  -> 生成私有 rebuild manifest（root/coverage/policy/index facts）
  -> fsync + staged replace
  -> 复验 manifest hash 与每个 archive manifest hash
  -> maintenance lease
  -> candidate import/validate
  -> reader drain + close writer
  -> 旧 DB/manifest/WAL/SHM/audit 隔离并写 inventory
  -> candidate pair publish + reopen
       失败：恢复旧完整派生集合，保持 KB_NOT_READY
       成功：保留 quarantine，不自动删除，不触碰原始导出
```

```text
release freeze + final manifest + relative evidence refs
  -> schema/policy/path/hash/batch 检查
  -> raw performance/UAT/audit/signature/recovery/rollback 重算与 join
  -> pass(0) | fail(1) | blocked(2)
  -> 只有 pass(0) + 无 blocker + approvals 才允许后续 publish
```

## 8. 关键设计决策

### 8.1 当前 formal gate 必须 blocked

外部输入和真实 Windows 证据缺失是发行事实，不是代码单测可替代的错误。保留 null + exit 2 能避免 synthetic fixture、macOS 构建或历史默认政策被误当正式通过。

### 8.2 不开放 recovery 路径字符串命令

方案要求 native picker 明确选择。当前先提供内部窄 seam 和行为测试，不让 frontend 自行构造路径；这避免为了“接线完整”而破坏目录授权边界。

### 8.3 FTS integrity 在私有备份副本上读写验证

SQLite FTS5 的 `integrity_check` 在只读连接上会因需要临时写入而失败。实现只对 `VACUUM INTO` 生成的 pending 私有副本开读写验证，绝不对 live DB 做该验证；通过后才提交 bundle。

### 8.4 quarantine 不自动清理

保留期限未获批，自动删除会扩大破坏面。因此成功发布后也只保留受管派生集合和 metadata inventory；用户原始导出从 allowlist 结构上排除。
