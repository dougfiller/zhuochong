## 1. 改动目标

- 对步骤 20/21 形成的同一 building index generation 做冻结配置、mapping、source/provenance、message/chunk/FTS/vector 和外键全量校验。
- 仅在校验摘要事务内重验一致后，用一个 `BEGIN IMMEDIATE` 同时切换 index/import/pointer/catalog。
- 候选失败或 denial 发生时保持旧完整 catalog 服务，并对不完整 active 组合、整会话 denial 或无法证明安全 provenance 的 scope 返回 `KB_NOT_READY`。
- 建立真实性能 JSON 的 fail-closed 验证器；在用户明确授权后，以可审计的受限默认政策解除 Windows 性能阻塞，同时保留 `not_run_user_waived` 事实边界。

## 2. 改动背景与基准

### 2.1 改动前状态

步骤 20 已持久化 building generation、candidate import mapping、chunk 与 FTS；步骤 21 已写 exact embedding BLOB 并支持 hybrid 查询。但仅有 `#[cfg(test)]` shortcut 能把 generation 标为 ready/catalog active，未重验完整性，也未原子切换 import status 与 conversation pointer。

## 4. 详细改动清单

- `0005_candidate_activation_diagnostics.sql`：增加 redacted `error_summary`、status/created 索引，并为旧 ready 行确定性补齐完成时间。
- `migrations.rs`：v4→v5 单事务迁移、schema 列/索引/状态不变式、迁移与非法状态测试。
- `store.rs`：新增 `CandidateValidationCounts/Digest`、`ActivationReceipt`、正式校验/激活 API；验证 snapshot/count/coverage/source/provenance/BLOB/FK；catalog sequence checked add + CAS；完整 active scope 与 denial safe proof。

- 两个新 verifier 及步骤 17/20 schema-head 静态 gate 兼容更新。

## 5. 处理流程或行为变化

`building + mapping + chunks/FTS + vectors` → reader 预检摘要 → `BEGIN IMMEDIATE` 全量重验 → import/pointer/index/catalog 同事务切换 → commit 后返回 receipt。任一步失败均不产生新 active catalog；denial 不再清空旧 catalog。

## 6. 输入、输出与接口变化

- 输入：`validate_candidate_index(index_generation_id)` 只接受现有 building id。
- 事务输入：`activate_validated_candidate(index_generation_id, expected_digest)`；不接受 caller 提供的 snapshot、dimension 或 sequence。
- 输出：crate-private receipt 只含 generation id、snapshot hash、sequence、激活时间和计数，不含正文、路径、exportId 或向量。

## 8. 关键设计决策

### 8.1 复用现有冻结与派生 primitive

校验直接复用 `load_frozen_build`、确定性 snapshot/source hash、chunk derivation、exact unit embedding decoder 和 SQLite FK 检查，避免第二套宽松实现。

### 8.2 预检摘要不是发布通行证

writer 事务内从数据库重算并精确比较摘要，再执行有 affected-row 校验的 DML 和 catalog CAS，关闭 TOCTOU。

### 8.3 性能证据严格分层

Rust/临时 SQLite/loopback 测试只作为功能证据。用户明确授权“和 win 相关的都默认通过”后，正式 JSON 以完整五项要求、授权原话、UTC 时间和固定范围启用受限政策分支；验证器退出 0，但 `evidenceStatus` 仍为 `not_run_user_waived`。这解除流程阻塞，不构成 Windows 实测证据。
