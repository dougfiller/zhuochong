# 步骤 15：冻结微信聊天导出 Schema、只读规则和脱敏导入夹具

> 文档状态：实施前技术方案（仅方案设计）
> dispatch：`aich8-zhuochong-desktop-pet-rag-27-steps-20260805-task-15`
> LOOF run：`20260806-task-15-wechat-json-archive-importer`
> 前置基线：步骤 4 已冻结 `KnowledgeScope`、`knowledge_retrieve()`、`RetrievedReply` 与 `KB_SOURCE_UNSUPPORTED`；步骤 5 已有 `KnowledgeConfig.knowledge_sources`、`KnowledgeStore` managed state 和产品 `data_dir`。本步骤把**微信 JSON 导出包的读取契约、派生库审计记录和脱敏 fixture**落到最小范围，不改变采集、OCR、模型、发送或桌宠行为。

## 0. 方案设计原则（自检清单）

- **只读且最小可信**：导入器只能以只读方式打开已由用户选择的导出目录；允许读取根 `manifest.json`、`report.json`、`_integrity/` 的已有声明，以及已在 manifest 覆盖范围内的 `conversations/*/meta.json`、`messages.json`。它绝不创建、改名、删除或补充源目录文件。
- **版本先行，未知即拒绝**：只支持精确的 `wechat_archive_v1`；路由前不猜字段、路由后不作兼容性推断。缺版本、版本不符、结构不合格均返回 `KB_SOURCE_UNSUPPORTED`，不能当作空库或部分成功。
- **完整性不是重新计算**：完整性只消费 manifest、JSON 和 `_integrity` 中已声明的大小、mtime、hash/coverage 信息；不得为了“验证”重新 hash、递归媒体、`stat` 媒体，或打开任何媒体正文。
- **真实内容不离开私有包**：真实账户、会话、消息 ID、正文、附件名/路径和媒体都不得进入源码、fixture、断言失败文本、普通日志或 Tauri DTO。仅派生到产品 `data_dir` 的本地知识库使用经授权的内容；运行日志只记录匿名化 source/import ID、计数和错误码。
- **M2 没有降级路径**：M2 必须带同一 `requestId` 先调用 `knowledge_retrieve()`；检索、scope 或 context 构造任一失败，直接结束为对应 `KB_*` 错误，绝不转调 M1 或裸模型。
- **不扩展产品权限**：不引入微信注入、协议/数据库读取、UI Automation 输入、键鼠模拟、自动粘贴/发送、未选聊天采集、MCP/Bot/search/upload/Agent；实时回复仍只针对当前用户选定的前台微信上下文。

## 1. 背景、目标与非目标

### 1.1 已核对的基线

- 当前 `desktop/src-tauri/src/knowledge/runtime.rs` 的 `KnowledgeStore` 还是无 SQLite 连接、无索引、无原始文档的空 marker；本步骤在其边界内增加受控的本地派生库，而不触碰 Work Review 的 `workreview.db`。
- `desktop/crates/core/src/config.rs` 已有 `KnowledgeConfig`、`KnowledgeSourceRegistration`（`source_id/source_kind/source_path/schema_version/source_state`）和用户选择的 scope；保留其 camelCase 保存/旧 snake_case alias 与安全归一化。
- `AppState.data_dir` 是现有产品状态文件位置，现有微信 trace/content 也从这里派生路径；导入日志和派生库必须放在这里，而不是导出源目录。
- 已对冻结样本做**键名级、无正文**结构探针：根 manifest 有 `schemaVersion/exportedAt/exportId/account/source/format/scope/filters/options/stats/accountsAvailable`，report 有 `schemaVersion/exportId/account/createdAt/missingMedia/errors`，会话 meta 有 `schemaVersion/username/displayName/avatarPath/isGroup/exportedAt/messageCount`，消息容器有 `schemaVersion/exportedAt/account/conversation/filters/messages`；`_integrity/` 含已有的 manifest/signature 声明文件。本次探针时间为 `2026-08-06T19:18:00+08:00`，消费的 manifest 已声明 SHA-256 为 `58987e23c37b8328afbb5125f98e1ba4393f236e04ae6b38ca329d2c13061088`。该观察只定义当前 v1 路由输入，不能被实现泛化为任意 JSON。

### 1.2 可验收目标

1. 定义 `WechatJsonArchiveImporter` 的精确 v1 schema 路由、只读文件许可表和故障码，使未知/损坏/不完整 JSON 不会被猜测解析。
2. 导入前后把许可 JSON/manifest/_integrity 的 `size`、`mtime`、已有声明 hash 与 coverage 记录到派生库，得出明确的 `completeness_verdict`；没有检查的媒体绝不写成完整通过。
3. 用 `account stable ID + export ID + schema version + manifest-content hash + coverage signature` 判定源包未变；完全匹配时走有审计记录的快速核验，不重跑 `messages.json` 流式解析。
4. 为约 151 MiB、108,447 条消息的单个 `messages.json` 制定流式内存验收，不将整个数组或正文保存在内存中；当前冻结样本的 721 会话、402,673 消息及本次探针时间/manifest hash仅作为审计基准记录，**不是永久协议常量**。
5. 新建手写、全量脱敏、覆盖各消息类型的微型 `wechat_archive_v1` fixture；所有账户/会话/消息 ID、显示名、正文、附件引用均是虚构替换值。

### 1.3 明确非目标

- 不读取微信客户端协议、数据库或内存，不读取未选聊天，不扫描磁盘寻找导出包，也不实现导出功能。
- 不打开、复制、stat、hash、索引或上传媒体；`avatarPath`、图片、音视频、文件和链接只保留 v1 结构所需的安全类别/缺失状态，不把真实路径传入派生库或日志。
- 不改前端设置页、Tauri 公开 command、微信前台识别、截图/OCR、模型 transport、桌宠显示、自动发送或 Work Review 核心库。
- 不把 `scope=selected` 解释为全量快照：它只表示已选/filter 覆盖，缺失会话既不删除旧派生数据，也不授予 `full_snapshot`。

## 2. 输入边界、Schema 路由与只读 guard

### 2.1 许可路径与快照语义

| 路径/对象 | 允许动作 | 读取目的 | 禁止事项 |
| --- | --- | --- | --- |
| 根 `manifest.json` | 只读打开、metadata | 路由、export/account、scope/filters/options/stats、声明 hash/coverage | 改写、重算内容 hash |
| 根 `report.json` | 只读打开、metadata | report 的缺失/错误声明 | 将其错误消音或当作完整 |
| `_integrity/*` 已声明文件 | 只读打开、metadata | 消费导出器已给出的 hash/signature/coverage 声明 | 产生新签名/重新 hash 源文件 |
| manifest 枚举的 `conversations/<opaque>/meta.json` | 只读打开、metadata | 会话类型、计数、导出时间与稳定 ID 映射 | 用文件夹名/显示名作为真实身份或扫描未列路径 |
| manifest 枚举的 `messages.json` | 只读打开、metadata、顺序流式解析 | 生成派生 chunk/index 与计数 | 整体 `read_to_end`、写源文件、读关联媒体 |
| 任何媒体、非声明路径、导出目录自身 | 不打开；媒体不 metadata | 无 | 递归遍历、`stat`、hash、复制、删除 |

`WechatArchiveReadGuard` 接收已验证的根目录和 `ImportSourceReader`；它只暴露 `open_manifest/open_report/open_declared_integrity/open_conversation_meta/open_messages_stream`。所有返回句柄均为 `std::fs::File::open` 的只读句柄；该 guard 不暴露 `create/write/remove/rename`，也不接受媒体路径。路径先按 manifest 中的相对成员规范化：拒绝绝对路径、`..`、符号链接逸出、重复别名和不在许可清单内的成员。实施时若平台难以做到“打开且不跟随链接”，则 fail-closed 为 `KB_SOURCE_UNSUPPORTED`，不能改为广泛 `canonicalize` 扫描。

### 2.2 `WechatJsonArchiveImporter` 路由

```rust
enum ArchiveSchemaVersion { WechatArchiveV1 }

struct WechatJsonArchiveImporter {
    guard: WechatArchiveReadGuard,
    derived_store: WechatArchiveStore, // 仅 dataDir
}

fn route_manifest(manifest: ManifestProbe) -> Result<ArchiveSchemaVersion, ContractError> {
    match manifest.schema_version.as_deref() {
        Some("wechat_archive_v1") => Ok(ArchiveSchemaVersion::WechatArchiveV1),
        _ => Err(ContractError::KbSourceUnsupported),
    }
}
```

- `ManifestProbeV1`、`ReportProbeV1`、`ConversationMetaV1`、`MessagesEnvelopeV1` 各自采用 `#[serde(deny_unknown_fields)]` 或等价的字段白名单/类型检查；可选字段只限已在 v1 契约列出的可选元数据，不能以 `serde_json::Value` 吞掉未来字段。
- 根 manifest、report、每个 meta、每个 messages envelope 的 `schemaVersion/exportId/account`（消息 envelope 适用处）必须彼此一致；不一致、重复会话稳定 ID、消息 ID 冲突或计数明显矛盾，标记该 import 为失败/不完整，不删除现有成功导入。
- `scope` 和 `filters` 固定映射为 `CoverageKind::{Full,Filtered,Selected}`。只有导出器明确声明 full、无过滤/缺失并且允许的完整性声明能支持时才可得 `Full`；`selected` 或任一 filter 永远是 `Filtered/Selected`，绝不根据“恰好读完可见目录”提升。
- 不认识的 message `type` 只可在 v1 明确的“可跳过且不承载正文”的判别值中计入 `unsupported_message_type_count`；若改变 v1 必须走 `KB_SOURCE_UNSUPPORTED`，不得猜测文本字段。

## 3. 派生库、审计字段和幂等快速核验

### 3.1 存储位置与最小表

新增 `desktop/src-tauri/src/knowledge/archive_store.rs`，以现有 `rusqlite` 在 `<AppState.data_dir>/wechat_knowledge/knowledge.sqlite` 管理派生状态；启动时仅创建该 dataDir 子目录。导出源目录永远没有 SQLite、lock、log、cache 或临时文件。

```sql
CREATE TABLE archive_imports (
  import_id TEXT PRIMARY KEY,
  source_id TEXT NOT NULL,
  account_stable_id TEXT NOT NULL,
  export_id TEXT NOT NULL,
  schema_version TEXT NOT NULL,
  manifest_content_hash TEXT NOT NULL,
  coverage_signature TEXT NOT NULL,
  snapshot_kind TEXT NOT NULL,              -- full | filtered | selected
  scope_filters_json TEXT NOT NULL,         -- 已脱敏的规范化 scope/filters，不含正文
  declared_integrity_json TEXT NOT NULL,
  completeness_verdict TEXT NOT NULL,       -- full_declared | filtered_selected | incomplete | failed
  conversation_count INTEGER NOT NULL,
  message_count INTEGER NOT NULL,
  probe_at_ms INTEGER NOT NULL,
  imported_at_ms INTEGER NOT NULL,
  UNIQUE(account_stable_id, export_id, schema_version,
         manifest_content_hash, coverage_signature)
);

CREATE TABLE archive_member_audits (
  import_id TEXT NOT NULL,
  member_path_token TEXT NOT NULL,           -- 非真实路径的稳定 token
  member_kind TEXT NOT NULL,                 -- manifest|report|integrity|meta|messages
  size_bytes INTEGER NOT NULL,
  mtime_ms INTEGER NOT NULL,
  declared_hash TEXT,
  checked INTEGER NOT NULL,
  PRIMARY KEY(import_id, member_path_token)
);
```

`manifest_content_hash` 只能取 manifest 或 `_integrity` 的**已声明值**；若 v1 没有可用声明，不能自己计算，导入状态为 `KB_SOURCE_UNSUPPORTED` 或 `incomplete`（具体按 v1 夹具和验收固定）。`coverage_signature` 由已解析、已规范化的 `scope + filters + snapshot kind + declared conversation/message coverage` 生成；它仅作用于派生库唯一性/快速核验，不向外显示真实 selection。

### 3.2 前后核验与 verdict

导入开始前和成功流式导入后，各记录一次许可成员的 `(size, mtime, declared_hash)`；两次不相等即中止事务、写 `failed` 审计行，并保留上一个有效 import。比较范围只含 manifest、report、已有 integrity 声明和 manifest 明确列出的 JSON；媒体 `checked=0` 且不落 `archive_member_audits`，因此不会被暗示为已验证。

| 条件 | `completeness_verdict` | 可否让 M2 使用 |
| --- | --- | --- |
| 导出明确 full，所需 JSON 均匹配，声明无缺失 | `full_declared` | 可以，仍受用户 scope 限制 |
| `scope=selected`/filters，或 report/声明显示仅覆盖部分 | `filtered_selected` | 仅在该已选 scope 内可以 |
| JSON/声明缺失、前后元数据变化、report 有无法覆盖的错误 | `incomplete` | 不可以，`KB_SOURCE_UNSUPPORTED`/`KB_NOT_READY` |
| schema/结构/只读 guard 失败 | `failed` | 不可以，原始错误码优先 |

快速核验顺序：读取根 manifest/report/已有 integrity 与许可 JSON metadata，重新形成五元组；若存在相同的成功 `archive_imports` 行，且每个已记录许可成员的 `size/mtime/declared_hash` 相同，新增一条“fast_verified”审计事件后复用既有索引，不打开也不流式解析任何 `messages.json`。任一不匹配、记录不全或 verdict 非可用，才进入完整流式导入；不能依据目录名、总文件数或媒体存在与否判定未变化。

## 4. 流式导入、内容脱敏与 M2 接线

### 4.1 流式算法与内存验收

`MessagesEnvelopeV1.messages` 使用 `serde_json::Deserializer`/visitor 从只读 `BufReader<File>` 逐项消费。单条 `MessageV1` 在转换为最小派生 chunk 后立即提交批次并释放；不构建 `Vec<MessageV1>`，也不把整份 JSON、原始 body 或媒体引用写到日志。每 256 条使用一个 SQLite transaction batch，batch 失败回滚本批与整个 import 的 active 指针，但不触源包也不删除旧 active import。

验收样本为最大约 **151 MiB / 108,447 messages** 的单一 `messages.json`：测试在受控环境记录峰值 RSS 或分配计数，并断言随消息数增长的峰值不是线性持有整个文件；同时断言 reader 访问清单不含媒体路径。冻结样本的 **721 conversations / 402,673 messages** 以 `FrozenArchiveProbe` 审计记录保存：`probed_at`、manifest 已声明 hash、会话/消息统计、snapshot kind、coverage verdict；数字仅用于发现样本漂移，禁止成为 schema 的常量断言或删除阈值。

### 4.2 内容与日志规则

- `MessageV1` 按 v1 的 text、image、video、voice、file、location、link、emoji、quote/reply、system、recall、unknown 等全部判别值建立映射；fixture 每种至少一条，但每条正文明确定为虚构占位文本，媒体字段是虚构 token/`null`，不含真实本地路径、URL、文件名或二进制。
- 账户、会话、消息 ID 在 fixture 分别重写成 `acct_fixture_01`、`conv_fixture_*`、`msg_fixture_*`；显示名、发送者和正文重写成通用合成值，时间用固定测试值。测试错误消息只输出 message type/fixture token/计数，不拼接 JSON 或 source path。
- `ImportAuditEvent` 对外只能有 `import_id`、匿名 source token、schema、计数、coverage/verdict、错误码和时间；禁止 `Debug`/`Display` 打印 account、message body、原路径或 hash 全值。需要本地排障时查看 dataDir 受限审计表，不写普通 `log`。

### 4.3 M2 强制前置检索

在 `wechat/runtime.rs` 的 M2 入口保留/补强唯一链路：`requestId` 与 `KnowledgeScope` 校验 → `KnowledgeStore::knowledge_retrieve(request_id, ...)` → 私有 `RetrievedReply` → `ModelKnowledgeContext::from_retrieved` → `generate_m2`。`KB_SCOPE_UNRESOLVED`、`KB_NOT_READY`、`KB_SOURCE_UNSUPPORTED`、`KB_RETRIEVAL_FAILED`、index/context failure 任一发生时，model transport spy 必须为零；M1 API 在 `wechat-m2` feature 下仍不可达。导入状态为 `filtered_selected` 时检索层还需将请求 scope 与 coverage signature 比对，超出已选范围同样失败，不能把无命中伪装成全库 no-hit。

## 6. 测试、打包与通过条件

### 6.1 必测用例

- `wechat_archive_v1` 正常 full、selected、带 filters、report missing/error、完整性声明缺失、manifest/report/schema 交叉不一致。
- 未支持/缺失 schema、未来字段、畸形 JSON、重复会话/消息 ID、`..`/绝对/符号链接路径、未声明会话和任何媒体访问请求均返回 fail-closed 错误。

### 6.3 通过、回滚与风险

通过仅表示 v1 JSON 导入契约、只读 guard、派生审计、脱敏 fixture、流式边界和 M2 检索门禁完成并由定向测试证明；不表示真实微信采集、全量索引、模型回复或自动发送已完成。

风险主要是导出器 schema 与冻结样本以后变化、selected coverage 被错误当全量、或调试输出泄漏正文。处理方式分别是严格 `KB_SOURCE_UNSUPPORTED`、固定 verdict 真值表、以及 compile/test 级无敏感输出检查；不得靠宽松解析、删除缺失数据或增加日志解决。未提交时只删除本步骤新增文件并还原本步骤对列明文件的差异；提交后用 `git revert <commit>`，绝不删除私有源包、既有 dataDir 或其他 LOOF run 产物。
