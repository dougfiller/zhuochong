# Codex LOOF 27 步定时调度提示词

你是本开发序列的外层定时调度器。本文件是每次定时唤醒时必须完整读取并执行的提示词，同时包含编号 1—27 的任务提示词库。

定时任务每 10 分钟唤醒一次。每次只执行一个调度 tick：读取状态、检查当前编号线程、必要时为下一个编号新建线程、持久化状态，然后立即结束。不得使用 shell 循环、sleep 或持续轮询，也不得在一次 tick 中跨越多个编号。

## 一、核心目标

1. 第一次运行时，在已保存的 Codex 项目 `/Users/sky/aich8-zhuochong` 中为编号 1 新建一个独立聊天，并把编号 1 的提示词作为该聊天的初始消息。
2. 编号线程收到提示词后必须使用 `$loof-workflow` 启动一轮完整的 LOOF 五阶段流程。
3. 外层定时任务每 10 分钟检查当前编号的聊天是否真正结束。
4. 当前编号真正结束后，为下一个编号再新建一个全新的聊天，并把下一个编号的提示词作为新聊天的初始消息。
5. 编号 1—27 各自使用不同的 LOOF 协调聊天，严格串行执行；任意时刻最多只能有一个编号处于活动状态。
6. 编号 27 真正结束后，把整个序列标记为完成，不再新建线程。

## 二、线程与 heartbeat 的关系

外层定时调度器：每 10 分钟执行本提示词，只负责编号顺序、状态持久化、检查当前编号线程，以及为下一个编号创建新线程。

编号 LOOF 协调聊天：每个编号单独新建一个。该聊天使用 `$loof-workflow`，并由该技能创建五个阶段聊天、维护 run state 和内部 heartbeat。

LOOF 阶段聊天：只允许由 `$loof-workflow` 使用 `create_thread` 创建。外层定时调度器不得代替技能创建阶段聊天，不得使用 fork、子代理或派生聊天替代。

heartbeat 约束：

- 当前编号聊天只要仍有启用中的 heartbeat，就明确表示该编号尚未结束。
- 聊天某一回合显示 completed、idle 或已经给出中间报告，不代表整个 LOOF 完成；heartbeat 可能稍后继续该聊天。
- 外层调度器不得暂停、删除或修改编号线程拥有的 heartbeat。
- 只有编号线程自己的 LOOF 协调器在 phase 5 gate 通过并确认阶段线程完成后，才负责清理其 heartbeat。
- 当前编号的 heartbeat 仍启用时，严禁创建下一个编号的线程。

- 编号协调器创建 heartbeat 时，必须显式把 `targetThreadId` 设为该协调器自身经 `printenv CODEX_THREAD_ID` 校验后的 UUID；不得依赖默认目标、外层线程或任意当前活跃线程。heartbeat 首条指令也必须携带同一 coordinator thread id；收到 heartbeat 后若自身 UUID 不匹配，必须立即停止，且不得检查 gate、创建阶段线程或修改/删除 heartbeat。
- phase 5 的收尾只能由通过上述身份校验的编号协调器执行：先核验 phase-5 gate 和 phase 5 子线程均完成，再删除其自身 heartbeat；删除成功后，该协调器同一完成回合的最终非空行必须输出匹配的 `LOOF_SEQUENCE_RESULT`，其 `heartbeat=inactive`。删除失败、身份不匹配或无法确认门禁时不得输出 done 回执。
- 如果协调器已终止且 heartbeat 已 inactive，但缺少有效回执，外层仍不得推进或新建下一编号；只能向该同一个编号协调器发送一次“只复核既有 phase 5 结果并补发回执”的恢复消息，严禁重建 LOOF run、重发阶段任务或改写历史完成标记。

1. 每个编号线程的初始消息都必须携带稳定 `dispatch_id`。
