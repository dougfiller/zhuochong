## 二、问题清单

1. **更新反馈错位(可用性)** — 触发按钮在页面顶部品牌卡内(L110–122),结果 banner 却渲染在整页最底部(L193–200)且 3 秒即逝(L78–84);「已是最新/发现新版」这一关键结论出现在视线之外,违反原则③(洞察应在层级顶端)。
2. **信息密度失衡(关于页核心问题)** — 版本/更新这组高价值信息被压成图标下方 10–12px 小字(L109–135),而三张营销式信任卡占据中屏主体(L168–184);「答案优先」应答的问题是:我在用什么版本?最新吗?这版改了什么?——第三问完全没有答案。
3. **无更新日志入口** — 仓库有维护完整的 `CHANGELOG.md`(123KB),界面上却无任何「本版有什么新东西/查看更新日志」;用户升级后无法感知变化。
4. **无致谢与许可** — 开源应用没有 License 声明、没有第三方依赖致谢(marked/DOMPurify 等在 Ask.svelte L5–6 实际使用);技术栈 pills 只有 4 个词(L186–191),既不完整也不可点。
5. **环境信息不可复制** — 版本 chip 无平台/架构/构建号;用户报 issue 时无法一键复制环境信息(GitHub 按钮就在旁边,动线断裂)。
6. **赞助动线权重过高且弹窗一次平铺 3 个二维码** — 赞助与 GitHub/数据目录并列一级按钮(L154–163);弹窗 `grid-cols-3` 无响应式降级(L247),窄窗挤压;两层放大遮罩(z-135/z-140,L206/L304)交互重。
7. **「打开数据目录」缺上下文** — 按钮孤立在动作行(L150–153),不说明目录里是什么、占多少空间;它本是「本地优先」信任主张的最佳证据,却与信任卡(L169–173)割裂。
8. **视觉 token 漂移(原则⑤)** — 弹窗 28px 圆角(L216)、trust 卡编号 kicker 等自成一套;dark 模式色值全部内联 hardcode(如 L113、L130),未走 token。

## 三、改版方案

### 信息层级(一屏)

```
页头:关于
├ 品牌+版本卡(featured 白卡)
│   左:图标 + Work Review + 一句话定位
│   右:版本块 —— v1.6.2 · macOS (arm64)
│        状态行:已是最新 · 2 小时前检查(就地反馈,取代底部 banner)
│        动作:检查更新(按钮态内联转圈)· 自动检查(文字开关)· 复制环境信息
├ 「最近更新」卡(答案优先:这版改了什么)
│   v1.6.2 · 7月20日:2–3 条摘要;v1.6.0 一条;→ 查看全部更新日志
├ 双栏
│   ├ 本地优先卡:数据只存本机一句话 + 当前占用 1.2GB / 上限 2GB(数字带参照)+ 打开数据目录
│   └ 参与与支持卡:GitHub(Star 数)· 反馈问题 · ♥ 赞助(次级链接,弹窗默认单列+切换)
└ 致谢行:依赖 pills(Tauri 2/Svelte/Rust/SQLite/marked/DOMPurify)+ 第三方许可 → · © 2026 · MIT
```

### 关键交互

1. **就地更新反馈**:`updateStatus` 移入版本块状态行(替换 L193–200 底部 banner),检查中/已是最新/可更新三态;发现新版时状态行变为「v1.7.0 可用 · 立即更新」主按钮,不再限时消失。
2. **更新日志卡**:构建期把 CHANGELOG.md 最近 2 个版本注入(或后端命令读取),默认摘要 3 条;「查看全部」外链 GitHub Releases 或内嵌滚动面板。
3. **复制环境信息**:一键复制 `Work Review v1.6.2 · macOS 15.5 (arm64) · Tauri 2` 到剪贴板,toast 确认;紧邻「反馈问题」形成报 bug 动线。
4. **信任三卡收编**:三段文案压缩为「本地优先」卡内的一句主张+两行要点,腾出密度给版本/日志;打开数据目录与占用量放同卡(占用数据可复用 `get_storage_stats`)。
5. **赞助降权**:入口改为「参与与支持」卡内 ♥ 文字链;弹窗改单列 tab 切换(微信/支付宝/BMC),移除二级放大层。
