# Work Review 设计语言总纲

> 本目录是 Work Review「数据页族」(概览 / 时间线 / 日报)的设计基准。设计语言由**概览改版(已定稿)**确立,基准文件为 [`assets/overview-mockup.html`](assets/overview-mockup.html) 与 [`assets/overview-mockup.png`](assets/overview-mockup.png)。时间线与日报的探索方案(本目录 `timeline.md` / `report.md`)全部在该语言内展开,不另起炉灶。

---

## 一、五条设计原则

### 1. 答案优先于数据(Answer-first)

**阐释**:这是一款"替你记录"的工具,用户打开页面时想知道的是"我今天过得怎么样",而不是"给我一堆数字自己算"。因此每个数字必须带参照系(较上周同日、占比、峰值标注、delta 箭头),页面顶部必须先给一句话洞察——把结论放在数据前面,数据成为结论的证据。后端 `get_insights`(夜间合成洞察)与 `get_work_sessions`(连续专注段)已具备产出"答案"的能力,前端的职责是给答案安一个固定的家(洞察条)。

**适用**:概览的 KPI 与洞察条;时间线的当日摘要;日报的 TL;DR 与统计行;一切"看数"场景。
**不适用**:管理与设置类界面(分类管理、隐私规则、清理记录)——这些是操作场景,要的是准确与可逆,不要在确认弹窗里塞洞察;原始明细(逐条记录、数据表)也保持中立呈现,答案不能替代可核查的原始证据。

### 2. 一个故事一张卡(One story, one card)

**阐释**:卡片按"叙事单元"切,不按"数据表"切。构成条 × 24 小时分布讲的是同一个故事("我的一天怎么分配"),所以合成一张「今日节奏」主视觉卡;反过来,把一段会话拆成十几张 30 秒记录卡,就是把一个故事撕成碎片。判断标准:如果两张卡的标题可以用同一句话概括,它们就该是一张卡;如果一张卡里要回答两个不相关的问题,它就该拆开。

**适用**:概览主视觉;时间线的会话卡(一段连续工作 = 一张卡);日报的章节(一个主题 = 一段)。
**不适用**:不要为了"合并"把无关内容硬塞一卡(如把设置项塞进数据卡);双栏明细(网站 × 应用)是两个并列故事,保持两张卡而非一张大表。

### 3. 层级 = 洞察 → KPI → 主视觉 → 明细双栏

**阐释**:页面自上而下是一条"从结论到证据"的阅读动线:一句话洞察(最浓缩)→ 带参照系的 KPI(四个关键答案)→ 主视觉卡(一图讲完当日/当周故事)→ 明细双栏(可下钻的证据)。层级同时约束视觉权重:越靠上越"轻而精"(文字、小图形),主视觉承担最大图形面积,明细行最密。

**适用**:概览严格执行四层;时间线与日报按各自形态映射(时间线:洞察 → 时刻尺 → 会话流;日报:洞察 → KPI → 文章 → 互证明细),允许某层退化但不允许颠倒顺序。
**不适用**:全屏沉浸态(截图放映模式)与弹窗内不套此层级;设置页沿用表单纵排逻辑。

### 4. 周 / 日模式差异化

**阐释**:「今天」回答"此刻与当日节奏",第一视角是小时;「本周」回答"哪几天重、模式是否健康",第一视角是天。切换范围时不能只换数据不换视角——周模式下按天柱状图上位为主视觉,小时分布退化为"典型一天"曲线。KPI 的参照系也随模式切换(日:较上周同日;周:较上周/本周均值)。

**适用**:概览的范围切换;日报未来的周报形态;任何带「今天/本周」分段控制器的页面。
**不适用**:时间线是天生的"日"页面,不强造周模式,而是通过入口链接把周视角引流回概览;单日详情弹层/放映模式内不出现周概念。

### 5. 视觉 token(唯一来源)

**阐释**:所有页面共用一套 token(见下表),差异只体现在布局与信息密度,不体现在圆角、字阶、配色上。历史上时间线曾使用琥珀/暖石色系(editorial 早期方向),与定稿的 slate/蓝体系形成"两个 App"观感——改版的第一步永远是把 token 拉回同一来源。

**适用**:亮色主题下的全部数据页;新组件先查表再造型。
**不适用**:暗色主题另有映射表(本纲只锁定亮色基准);系统原生控件(日期选择器、文件对话框)不强行覆写。

## 三、分类色板与校验说明

六色是全产品分类的唯一色板,图表、chip、时间线标记、图例共用:

| 分类 | Hex | 色相/明度定位 |
|---|---|---|
| 开发 | `#3b82f6` | 蓝,中明度(亦为主色,开发=产品的"主线活动") |
| 会议 | `#d97706` | 琥珀橙,高明度暖色 |
| 文档 | `#8b5cf6` | 紫,中明度 |
| 沟通 | `#059669` | 绿,深暗色 |
| 娱乐 | `#be123c` | 深玫红,全板最暗的彩色 |
| 其他 | `#94a3b8` | 灰(slate-400),低饱和,永远视觉退后 |

**校验说明**:该组合已通过色觉可分性校验(红绿色盲 deuteranopia/protanopia 与蓝黄色盲 tritanopia 模拟)。可分性的来源不只靠色相,还刻意拉开了**明度阶**:蓝(中)/橙(亮)/紫(中)/绿(暗)/玫红(最暗)/灰(低饱和),在任一色盲模拟下相邻段仍有明度或饱和度差。使用时的三条冗余规则:① 图例顺序全局固定(开发→会议→文档→沟通→娱乐→其他),位置本身携带信息;② 图例与 tooltip 必带文字与数值,不允许"纯色编码";③ 堆叠图相邻段之间保留 2px 间隙,弱化色差依赖。新增自定义分类时应从该六色的间隙色相取色,并复检明度不与相邻类目撞车。
