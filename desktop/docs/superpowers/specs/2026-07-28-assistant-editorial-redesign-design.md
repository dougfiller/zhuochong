# 助手页 Editorial 视觉与交互优化设计

**日期：** 2026-07-28  
**状态：** 已获方向确认，待规格复核  
**范围：** 仅优化助手页前端视觉与交互呈现；保留现有对话、流式输出、工具调用、引用、模型选择和历史会话能力

## 一、背景与目标

概览与日报正在统一到干净、清爽的 editorial 数据页语言：浅灰页面底、白色内容面、22px 一级圆角、slate 文字阶、蓝色主操作，以及“先给结论、再给依据”的信息层级。

助手页已有完整能力，但当前页面更像通用聊天窗口：页面标题和数据上下文较弱，工具步骤比答案更抢眼，引用层级过深，历史会话入口不够明显，底部输入区的次要操作较分散。

本次目标：

1. 让助手页与概览、日报看起来属于同一个产品。
2. 让用户进入页面后能立刻理解助手可参考的数据范围。
3. 优先展示答案，把工具执行过程收拢为次级状态。
4. 让引用容易核查，让历史会话和新对话容易发现。
5. 保持现有业务流程、请求隔离、流式渲染和会话持久化行为不变。

## 二、非目标

本轮不包含：

- 修改 Rust/Tauri 后端接口或工具能力。
- 新增“今天 / 本周 / 自定义”真实查询范围参数。
- 重写消息存储结构、会话标题生成或模型配置流程。
- 实现引用跳转到时间线/日报的深链接。
- 重构时间线页面；时间线另行实施。

数据范围条本轮只展示当前可可靠获得的上下文，不伪造尚未接入的范围切换能力。

## 三、视觉方向

### 3.1 页面骨架

助手页采用与概览、日报一致的页面容器：

1. 页头：标题“助手”与当前会话摘要。
2. 页头操作：历史会话、新对话。
3. 数据上下文条：说明助手正在参考的可用数据与模型状态。
4. 主内容区：欢迎态或消息流。
5. 底部固定输入区：问题输入、模型选择、发送/停止。

页面使用浅灰底，主要回答与欢迎内容使用白色卡片面；不使用大面积渐变和高饱和装饰。

### 3.2 Token 对齐

沿用数据页设计基准：

- 一级卡片圆角：22px。
- 内嵌区域圆角：14px。
- 页面底：`#f4f6f9` 对应主题变量。
- 主内容面：白色。
- 主文字：slate-900；正文：slate-600；辅助：slate-400。
- 主操作：蓝色；危险操作：rose；执行成功：emerald；待确认：amber。
- 阴影保持轻量，仅用于底部输入区和浮层。

暗色主题继续使用现有 GitHub dark 映射，不另造新的暗色体系。

## 四、信息架构与状态设计

### 4.1 页头

- 左侧显示页面标题和当前会话标题；没有会话时显示能力说明。
- 右侧提供“历史会话”和“新对话”两个明确按钮。
- 历史会话按钮展示已有会话数量，但不改变现有抽屉数据结构。
- 生成过程中仍允许查看历史入口的视觉状态，但不改变当前请求隔离规则。

### 4.2 数据上下文条

- 展示当前日期、当前模型，以及助手可调用的本地数据类型等可靠信息；不展示尚未稳定接入的统计数字。
- 不实现虚假的时间范围切换器。
- 未配置模型时，清楚提示当前使用基础模板或需要前往设置。
- 该区域是信息提示，不成为新的业务状态源。

### 4.3 欢迎态

- 欢迎文案从居中“英雄区”收敛为轻量内容区。
- 动态 starter 与固定 starter 的生成逻辑不变。
- starter 使用简洁的白色/浅色卡片，强调问题文本，减少装饰性图标和渐变。
- 保持键盘与点击可访问性。

### 4.4 用户消息

- 保持右对齐，但改为浅蓝色气泡和细边框，避免渐变过强。
- 内容宽度保持适合短问题扫读，不扩大为整行卡片。

### 4.5 助手回答

- 每轮助手回答使用独立白色内容卡，形成“一轮回答一张卡”。
- 答案正文是视觉主角，工具过程位于正文之前的一条紧凑状态摘要中。
- 流式光标、Markdown 渲染、代码块、表格等现有行为不变。
- 取消重复的双加载表现：同一轮只保留一个清晰的生成状态。

### 4.6 工具执行过程

- 多个步骤默认汇总为一条状态胶囊，如“已完成 3 步”。
- 运行中显示当前步骤；失败与待确认必须显著可见。
- 用户可展开查看每一步细节。
- 待确认动作仍自动展开，并保留批准/拒绝操作，不能因视觉收拢而隐藏关键决策。

### 4.7 引用

- 消息级引用从双重折叠改为回答卡内的引用区域。
- 少量引用直接平铺；较多引用允许收起，但入口必须明确。
- 引用卡继续展示来源类型、日期、应用、时长、标题和摘录。
- 本轮不新增跳转链接；没有可靠目标时不渲染伪链接。

### 4.8 底部输入区

- 输入区保持 sticky，宽度与主内容一致。
- textarea 继续自适应高度并支持 Enter 发送、Shift+Enter 换行。
- 模型选择、快捷键提示、发送/停止集中在同一层级。
- 发送时右侧主按钮切换为停止按钮，避免停止操作远离焦点。
- “历史会话”和“新对话”从输入区移到页头，减少底部噪音。

### 4.9 历史会话抽屉

- 保留现有右侧抽屉和焦点管理。
- 调整标题、时间/消息数层级和选中态，使其对齐 editorial 风格。
- 删除按钮改用垃圾桶语义图标。
- 本轮不新增重命名、分组或删除确认逻辑，以避免扩展业务范围；危险操作沿用现状，后续单独治理。

## 五、响应式与可访问性

- 桌面端主内容宽度与概览、日报保持相近的阅读尺度。
- 窄屏下页头操作可换行，回答卡和输入区不得横向溢出。
- 保留现有 RTL 兼容方式和 `data-locale`。
- 交互按钮必须有可见焦点态、`aria-label` 或可读文本。
- 抽屉继续支持 Esc 关闭和 focus trap。
- 颜色不能成为步骤状态的唯一表达，继续配合文本/图标。

## 七、测试与验收

### 自动化测试

1. 页头存在历史会话和新对话入口。
2. 欢迎态 starter 仍可提交问题。
3. 发送中的页面只出现一套生成状态。
4. 工具步骤可汇总、展开，待确认操作仍可见。
5. 引用信息未丢失且不再出现不必要的双重折叠。
6. 模型选择、Enter/Shift+Enter、停止生成入口仍存在。
7. 历史抽屉 Esc、切换、删除入口保持可用。
8. 中英文、繁体中文、阿拉伯语新增文案完整。

### 构建与视觉验收

- 运行助手相关 Node 测试，单次命令超时不超过 60 秒。
- 运行完整前端测试与 `npm run build`。
- 在亮色、暗色主题检查欢迎态、会话中态、流式态、引用态和历史抽屉。
- 检查常见桌面宽度与窄屏布局。
- 与概览、日报对照圆角、面色、按钮和文字层级。

## 八、风险与控制

- `Ask.svelte` 体积较大：优先只调整派生状态和模板结构，不重写请求主流程。
- 流式状态复杂：通过现有 `AssistantStreaming`、请求隔离和 Ask 专项测试防止回归。
- 全局 CSS 已有未提交改动：新增样式使用 `ask-editorial-*`/现有 `ask-*` 命名域，避免覆盖概览和日报选择器。
- 多语言长度差异：页头、上下文条和输入区使用 flex wrap 与最小宽度控制。

## 九、验收标准

完成后应满足：

1. 用户一眼可识别当前页面、当前会话和主要操作。
2. 回答比工具执行过程更突出。
3. 引用无需穿过两层折叠才能查看。
4. 输入区只保留与当前提问直接相关的操作。
5. 视觉上与概览、日报属于同一套产品语言。
6. 现有助手业务能力和流式可靠性测试无回归。
