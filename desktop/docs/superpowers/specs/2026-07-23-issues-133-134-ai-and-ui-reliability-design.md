# Issues #133 / #134：AI 调用与界面可靠性设计

## 背景

Issue #133 报告：设置页的 AI 连接测试成功，但助手仍返回基础模板，日报也提示 AI 请求失败并回退。代码检查确认助手前端已传递所选模型配置，问题出在后端路由顺序：身份、问候和能力类问题会在检查 `has_model` 之前进入固定回答，因此即使用户明确选择了 AI 模型，也不会发起模型请求。

日报生成与设置页连接测试使用不同的请求路径。连接测试是短请求，日报则上传统计摘要并等待较长生成结果。日报命令外层允许 300 秒，但云端摘要 HTTP 客户端当前只允许 90 秒；同时，失败原因只粗略区分“配置不可用”和“请求失败”，不足以判断是超时、网络、服务端状态码还是响应内容异常。没有用户 API Key，因此当前不能把日报失败归因于某个具体提供商或模型格式。

Issue #134 包含三个界面问题：`ui-style-a`（“专业清爽”）在深色模式下继续使用浅色边框；时间线工具栏按钮内部图标偏小；助手空会话页的推荐问题在可用高度不足时与欢迎区域或输入区域挤压重叠。

## 目标

1. 用户明确选择可用 AI 模型时，助手的所有自然语言问题都进入 Agent，包括“你是谁”“你好”等身份和问候问题。
2. 用户选择基础模板或没有可用模型配置时，继续使用现有 Direct、Fast 和 Fallback 模板能力。
3. 日报 AI 请求有足够时间完成长内容生成，同时在失败后安全回退并给出可操作的失败类别。
4. 修复“专业清爽”深色模式的浅色卡片边框，不影响其他视觉风格。
5. 放大时间线工具栏图标，但保持按钮尺寸、点击区域和布局不变。
6. 让助手空会话欢迎内容在常见窗口尺寸和缩放比例下保持正常文档流；高度不足时可以滚动，不与输入框重叠。
7. 为上述行为增加针对性回归测试，并通过现有构建与相关测试。

## 方案选择

### 方案 A：针对性稳健修复（采用）

- 调整助手路由优先级，让显式模型选择高于固定问候模板。
- 保留日报现有分析器和自动回退机制，扩大请求时间预算并细化安全错误分类。
- 用作用域明确的 CSS 和组件类修复三个视觉问题。
- 通过 Rust 单元测试和前端源码/构建测试覆盖回归。

该方案直接覆盖两个 Issue，避免引入跨模块 AI 客户端重构，风险和收益最平衡。

### 方案 B：最小补丁（不采用）

只移动路由判断、把 90 秒改成更大数值并修 CSS。实现较快，但日报失败仍只显示笼统信息，下一次模型兼容或网络问题仍难排查。

### 方案 C：统一 AI 传输层（暂不采用）

让连接测试、助手和日报共用一个 Provider Client。长期一致性最好，但会同时影响设置、Agent、日报和多个提供商，范围超过本次两个 Issue。

## 详细设计

### 1. 助手路由：显式模型选择具有最高优先级

`Ask.svelte` 继续通过 `getSelectedModelConfig()` 把当前选择的模型配置传给 `chat_work_assistant`，不改变前端配置协议。

`route_query(question, has_model)` 的顺序调整为：

1. `has_model == true`：直接返回 `QueryPath::Agent`，由模型判断意图、是否查询工作记录以及如何回答。
2. `has_model == false`：身份、问候和能力类问题进入 `QueryPath::Direct`。
3. 无模型的工作查询进入 `QueryPath::Fast`。
4. 其余无模型问题进入 `QueryPath::Fallback`。

这样，“基础模板”仍能即时回答身份问题；一旦用户选择 AI 模型，界面选择就成为权威来源，不再被固定模板静默截获。

模型可用性的现有判断保持不变：配置至少需要非空 endpoint 和 model；本次不强制所有提供商都必须有 API Key，以免破坏 Ollama 等本地服务。

### 2. 日报 AI 请求：长请求预算与安全失败分类

保留 `SummaryAnalyzer` 和现有 OpenAI-compatible URL 生成逻辑，不针对 SiliconFlow 或 Kimi 写硬编码分支。

将摘要 HTTP 请求时间预算提升到适合长报告生成的范围，并明确小于日报命令的 300 秒外层截止时间。实现采用共享常量表达两个截止时间，摘要请求目标为 240 秒，给线程调度、回退报告组装、保存数据库和返回 IPC 预留约 60 秒。所有远程和本地摘要请求遵循同一明确上限，避免客户端 300 秒与外层 300 秒同时到期的竞争。

日报仍遵循“AI 失败不阻止报告生成”的行为：

- 成功且返回非空内容：保存 AI 增强报告和模型名称。
- 返回空内容：回退基础模板，并标记“模型返回空内容”。
- 配置或认证问题：回退并标记“AI 配置或认证不可用”。
- 请求超时或连接失败：回退并标记“AI 请求超时/网络连接失败”。
- 服务端非成功状态：回退并标记“AI 服务返回错误”；日志保留状态码和经过截断的诊断信息。
- 响应 JSON 或内容格式异常：回退并标记“AI 响应格式异常”。

用户可见的 `fallback_reason` 只显示本地化后的安全类别和“已回退到基础模板”，不回显 API Key、完整请求、完整响应或内部路径。日志用于开发排查，但同样不得记录 Authorization 头和 API Key。

连接测试仍保持短超时，因为它的职责只是验证基本连通性；设计不把连接测试成功等同于长报告一定成功。

### 3. “专业清爽”深色边框

在 `src/app.css` 的 `ui-style-a` 深色规则中显式定义深色 surface border token，并在浅色 `ui-style-a` 卡片规则之后应用。覆盖范围限制为该风格重新定义过边框的页面卡片和柔和卡片，包括 `.page-card`、`.page-card-soft` 及实际受同类覆盖影响的设置/信息 surface。

不使用全局 `.dark * { border-color: ... }` 一类规则，避免改变输入框、强调卡、状态色边框和其他视觉风格。深色边框应采用现有 GitHub-dark 风格的中性灰层级，与项目已有 `rgba(71, 85, 105, 0.5)` 附近的边框一致。

### 4. 时间线工具栏图标

仅调整时间线顶部工具按钮内删除、刷新和截图图标的视觉尺寸，使用统一的 toolbar icon class 或统一尺寸类。按钮本身的宽高、间距、圆角、tooltip、disabled 状态和点击处理全部保持不变。

图标应从当前偏小尺寸提高一个视觉层级，但不得超出按钮安全内边距，也不得导致工具栏宽度变化。

### 5. 助手欢迎页布局

空会话欢迎页继续包含标题、副标题和最多四个推荐问题，不重新设计内容。

布局调整遵循以下规则：

- 欢迎标题区和推荐问题区保持普通文档流，不使用绝对定位或负 margin 拉叠。
- 移除会迫使内容在不足高度中垂直居中的脆弱组合，改为带最小顶部/底部间距的自适应布局。
- 推荐问题区与标题区保持明确间距；小高度窗口使用更紧凑的 padding，但不压缩为重叠。
- 聊天滚动区域继续为输入框保留底部空间；内容超过可用高度时由现有滚动容器滚动。
- 对窄窗口继续使用单列推荐问题，对可用宽度足够的窗口保持双列。

输入框仍位于工作台底部，现有模型选择、发送按钮、自动增高和流式消息逻辑不变。

## 测试设计

### Rust 路由测试

更新 `orchestrator.rs` 的路由单元测试，至少覆盖：

- `has_model=true` 且问题为“你是谁”时返回 `Agent`。
- `has_model=true` 且问题为问候或普通自由问题时返回 `Agent`。
- `has_model=false` 且问题为“你是谁”时仍返回 `Direct`。
- `has_model=false` 且问题为工作统计查询时仍返回 `Fast`。
- `has_model=false` 且问题不受支持时仍返回 `Fallback`。

### Rust 日报测试

在 `summary.rs` 中以纯函数或本地 mock 覆盖：

- 摘要请求截止时间为 240 秒，并小于 300 秒外层截止时间。
- SiliconFlow 风格的 `/v1` endpoint 仍生成唯一且正确的 `/chat/completions` URL。
- 超时、网络、认证/配置、HTTP 服务错误、响应格式异常和空内容映射到对应安全 fallback reason。
- 错误分类不会把 API Key 或完整远程响应拼入用户可见文本。

测试不调用真实第三方 API，也不要求用户凭据。

### 前端视觉回归测试

沿用项目现有的源码断言测试风格，覆盖：

- `ui-style-a` 深色规则在浅色规则之后显式覆盖 surface border color。
- 时间线三个工具图标使用统一且放大的尺寸，而按钮尺寸保持原值。
- 助手欢迎区不存在绝对定位/负 margin 叠放，具有可滚动和输入框预留空间所需的布局类或 CSS 规则。

最后运行相关 Node 测试、Rust 测试和 `npm run build`。如仓库已有更完整的统一测试命令，再执行不依赖真实外部服务的完整测试集。

## 验收标准

1. 选择 AI 模型后询问“你是谁”，路由结果为 Agent，不再直接返回基础身份模板。
2. 选择基础模板时，身份问答和工作统计模板行为保持可用。
3. 日报 AI 长请求不会在 90 秒时提前超时，失败时仍能生成基础报告。
4. 日报 fallback reason 能区分主要失败类别，同时不泄露密钥或完整服务端响应。
5. “专业清爽”深色模式的 Overview、Report、About 等卡片使用中性深色边框，不出现浅白描边。
6. 时间线删除、刷新、截图图标清晰增大，按钮点击区域和排列不变。
7. 助手推荐问题不与标题或输入框重叠；窗口较矮时可以正常滚动访问。
8. 针对性测试、Rust 测试和前端构建通过。

## 非目标

- 不在本次统一连接测试、助手和日报的全部 AI Provider Client。
- 不为 SiliconFlow、Kimi 或其他单一厂商增加专属请求格式。
- 不修改模型配置数据结构、迁移已有配置或改变连接测试语义。
- 不保证所有第三方模型都能在 240 秒内生成任意长度内容；超时后仍以可用的基础报告为优先。
- 不重新设计时间线工具栏、助手输入框或“专业清爽”主题。
- 不依赖真实 API Key 完成自动化测试。
