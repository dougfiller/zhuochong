# Work Review 概览交互与全应用细节优化设计

**日期：** 2026-07-28  
**状态：** 待用户书面复核  
**采用方案：** 方案 A——语义修正 + 轻量内联  
**范围：** 概览常驻网站与今日节奏、概览对齐、助手与关于页头、助手模型标签、macOS 原生标题、设置隐私页

## 1. 背景与目标

本轮不是整体重做，而是在现有概览视觉体系上修正数据语义、减少无效控件并统一页面细节。

目标：

- 常驻网站在多个浏览器场景下仍能准确表达网站总量和来源。
- 点击网站后只查看该网站的跨浏览器聚合详情，不混入其他网站。
- 今日节奏的分类构成可以直接点击查看，同时保持页面简洁。
- 删除价值较低、理解成本较高的横纵图表切换。
- 让概览、助手、关于和设置页使用一致的页面轴、边界和留白。
- 修复助手顶部模型名称不随底部选择更新的问题。
- 隐藏 macOS 窗口控制按钮旁多余的原生标题文字。
- 隐私设置改成扁平、易扫描、符合现有深浅主题的结构。

不追求：

- 新增完整活动级分类时间线。
- 区分同一浏览器的不同用户配置文件。
- 引入新的抽屉、复杂筛选器或全新导航。
- 重做应用整体视觉语言或后端数据模型。

## 2. 设计原则

### 2.1 数据实体必须一致

列表展示什么实体，点击后的详情就继续展示该实体。常驻网站列表以“域名”为实体，因此详情也必须以域名为中心。

### 2.2 文字优先于装饰图标

域名本身已经具有稳定识别能力，不再使用不统一的 favicon、浏览器图标和域名缩写。浏览器只作为来源数据展示，而不是网站身份。

### 2.3 内联详情优先

分类详情和规则编辑优先在当前区域内联展开。只有内容规模确实需要独立空间时才使用弹窗；本轮不新增抽屉。

### 2.4 删除低价值切换

当一种展示形式已经能完成主要任务时，不为“可切换”而保留第二种低效布局。今日节奏仅保留竖向 24 小时图。

### 2.5 容器居中，结构化内容按语义对齐

汇总数字、空状态和短状态可以居中；域名、应用、规则、图表标签和正文仍保持逻辑方向起点对齐。

### 2.6 深色模式使用共享边界

外围边线使用应用已有中性边界 token。禁止亮白描边、重复内边框和强内高光。

## 3. 方案选择

### 方案 A：语义修正 + 轻量内联（采用）

- 常驻网站以域名为中心并聚合多个浏览器来源。
- 移除域名缩写和浏览器图标，改用文字、分类细色标和来源比例轨道。
- 分类构成条可点击并在图表下方内联展示摘要。
- 删除横纵模式切换。
- 页头、模型标签、窗口标题和隐私设置同步轻量修正。

优点是逻辑正确、交互层级少、视觉最干净。

### 方案 B：保留明细列表切换（不采用）

把图标切换改成“节奏图 / 明细列表”文字分段控件。功能更显式，但会继续维护两套布局和状态，不符合精简目标。

### 方案 C：统一使用右侧抽屉（不采用）

域名、分类和隐私编辑均进入抽屉。空间充足，但层级更多、操作距离更长，不符合用户要求。

## 4. 常驻网站：数据与交互设计

### 4.1 当前问题

当前列表使用 `domain_usage`，按域名聚合；点击后却通过 `browser_usage` 找到该域名使用最多的浏览器，再展示该浏览器访问过的全部网站。

这会造成：

- 被点击域名在其他浏览器中的时长和 URL 丢失。
- 详情混入主要浏览器访问的其他网站。
- “查看全部”只打开第一个浏览器，并非全部网站。
- 单日域名在数据库层截断为前 10，日期范围统计可能漏掉累计常驻网站。

### 4.2 统一领域模型

前端为每个域名形成以下展示模型：

```text
DomainUsagePresentation
├── domain
├── totalDuration
├── category
├── pageCount
├── urls[]
└── browserSources[]
    ├── browserName
    ├── duration
    ├── percentage
    └── urls[]
```

数据规则：

- `totalDuration` 以域名聚合总时长为准。
- `browserSources` 从浏览器维度反向汇总到当前域名。
- 同一 URL 在多个浏览器中出现时按 URL 合并总时长；详情可保留来源分布。
- 来源占比使用浏览器在该域名上的时长除以该域名可归属浏览器的总时长。
- 无法归属到浏览器的剩余时长仍计入域名总时长，并标记为“其他来源”，避免占比虚假补齐。
- 浏览器同名归一化沿用现有规则；本轮不区分用户配置文件或同名不同安装路径。

### 4.3 列表外观

每一行不再显示缩写印章或浏览器角标：

```text
│ github.com                                  1小时32分
│ 12 个页面 · 编码开发
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
│ Chrome 58% · Safari 42%
```

视觉规则：

- 左侧使用 2–3px 的分类语义细线或小圆点，不使用大面积色块。
- 域名是第一层信息。
- 时长在行尾，与域名基线对齐。
- 页面数和分类是第二层弱信息。
- 总使用量轨道使用中性底色；多浏览器来源用同一主色的不同明度或稳定中性色区分，避免彩虹化。
- 单一浏览器时默认不显示来源文案；多个浏览器时显示前两个来源及占比。
- 超过两个浏览器时显示前两个来源，并追加“等 N 个来源”或“来自 N 个浏览器”。
- 轨道和文字均提供含义，颜色不是唯一信息载体。

### 4.4 点击域名

点击网站行后打开现有详情浮层，但详情实体改为域名：

- 标题显示域名、总时长、页面数和分类。
- 来源区域显示该域名在各浏览器中的时长与占比。
- 页面区域只显示该域名的 URL，不显示其他域名。
- URL 按聚合时长倒序排列。
- 每条 URL 可显示来源浏览器的简短文字，不使用浏览器图标。
- 关闭方式、焦点管理和键盘行为沿用现有浮层能力。

### 4.5 查看全部

“查看全部”打开所有域名列表，而不是第一个浏览器：

- 按域名总时长倒序。
- 每个域名沿用列表行的无图标表达。
- 选择其中一个域名后进入该域名详情。
- 页脚站点数量必须使用真实统计数量，不能使用已截断数组长度冒充全量。

### 4.6 数据完整性边界

为了避免跨日统计基于“每日前 10”二次合并，本轮需要取消或后移域名截断：

- 数据库聚合必须在截断前完成日期范围合并，不能再基于每日前 10 二次汇总。
- 概览统计只返回前 6 个域名摘要和真实唯一域名总数，避免把完整 URL 集合塞入首页载荷。
- “查看全部”通过独立域名摘要查询取得当前日期范围内的完整域名集合；摘要不携带 URL 明细。
- 点击域名后通过独立域名详情查询读取该域名在当前日期范围内的完整 URL 与浏览器来源。
- “完整/全量”明确指当前选定日期或日期范围、应用现有隐私过滤之后的全部可见域名数据。
- 浏览器来源数据继续沿用现有采集字段，不新增浏览器 profile 字段。

## 5. 今日节奏：分类点击与图表简化

### 5.1 分类构成条可点击

构成条中的每个分类分段改为可访问按钮：

- 点击分类后进入选中状态。
- 选中分段保持正常饱和度，其余分段降低透明度但仍可辨识。
- 再次点击当前分类、点击清除入口或切换日期时取消选择。
- 支持键盘焦点、Enter 和 Space。
- 提供包含分类名、时长和占比的可访问标签。

### 5.2 分类内联摘要

选中分类后，在今日节奏图表下方展示紧凑摘要：

```text
编码开发                         3小时24分 · 42%
活跃时段  09:00–11:00、14:00–16:00
主要应用  PyCharm 1小时30分 · Terminal 58分
```

内容范围：

- 分类总时长。
- 占总活动时间比例。
- 最活跃的小时或连续时段。
- 使用时长最高的若干应用。

本轮不展示：

- 完整活动记录。
- 截图。
- 分类下全部 URL。
- 跨日逐条时间线。

### 5.3 图表联动

- 选中分类后，24 小时图仅强调该分类的分段。
- 其他分类不删除，只降低视觉权重，避免用户误以为数据消失。
- 已选小时详情继续可用；小时与分类同时选中时，小时详情优先展示该小时内所选分类的应用。
- 清除分类后恢复当前小时的完整应用明细。

### 5.4 隐私过滤口径

分类总量、小时分布和应用明细必须使用相同的忽略应用与排除域名规则：

- 后端小时应用明细同步应用排除域名规则。
- 顶部分类时长继续使用概览统计结果作为权威总量。
- 前端派生摘要不能重新引入被隐私规则排除的数据。
- 添加覆盖排除域名后分类总量与小时明细一致性的测试。

### 5.5 删除横纵模式切换

- 移除今日节奏右侧的横纵图标切换。
- 只保留竖向 24 小时节奏图。
- 移除 `overview.hourlyActivity.viewMode` 的读取、写入和模式状态。
- 删除不再使用的横向 24 行布局及对应专用文案、样式和测试断言。
- 小时点击和分类点击承担全部下钻能力。

## 6. 概览内容对齐

### 6.1 居中内容

以下内容使用稳定的居中容器或文字对齐：

- KPI 卡片的主数值与简短辅助值。
- 今日节奏顶部的摘要数值。
- 无数据空状态、加载失败提示和短状态说明。
- 选中分类后的总时长与占比汇总区域。

### 6.2 保持逻辑方向起点对齐

以下内容不强制居中：

- 页面标题和工具栏。
- 常驻网站域名、来源说明与 URL。
- 应用使用列表。
- 图表坐标、图例和分类明细。
- 长说明文字。

### 6.3 布局原则

- 页面主内容轴保持水平居中。
- 卡片内部不为追求形式统一而破坏信息扫描顺序。
- RTL 语言继续使用逻辑属性，不写死 `left`/`right`。

## 7. 助手与关于页头

### 7.1 页面轴

助手页：

```text
页头：操作轴（约 78rem）
上下文提示：阅读轴（约 52–64rem）
欢迎态/对话：阅读轴
底部输入器：阅读轴
```

关于页：

```text
页头：操作轴
主体：阅读轴
```

这样左上页头与概览、时间线和设置一致，同时正文不会被过度拉宽。

### 7.2 助手页头结构

助手页头改用应用统一的页头语义：

- 标题组。
- 轻量徽标或现有页面标识。
- 一行简短说明。
- 右侧历史会话和新对话操作。

不在标准页头外再叠加第二层底部间距或边线。

### 7.3 助手模型标签修复

当前顶部模型标签通过无参数函数间接读取响应式状态，异步加载配置或切换模型后不会稳定重新计算。

改为显式派生值：

```text
selectedModelId + modelProfiles + locale
→ currentModelLabel
```

规则：

- 顶部上下文条与底部选择器统一使用 `currentModelLabel`。
- 选择模型后立即同步显示下一次请求将使用的模型。
- 模型配置异步加载完成后自动刷新。
- 切换语言后显示对应本地化名称。
- 生成中的历史回答不宣称使用新选择的模型；顶部文案表达“当前选择/下一次请求”，避免与正在生成的请求混淆。
- 将标签解析提取为可单测纯函数，避免再次出现隐藏依赖。

## 8. macOS 原生窗口标题

用户所指的红黄绿窗口按钮旁 `Work Review` 来自 Tauri 原生窗口标题，不是页面 DOM。

处理方式：

- 在 Tauri 窗口配置中启用 `hiddenTitle: true`。
- 保留窗口标题元数据、系统窗口控制按钮和现有透明标题栏。
- 不把应用标题改为空字符串。
- 不删除 macOS 原生装饰。
- 不修改侧边栏中的产品品牌文字。

验收结果是 macOS 标题栏只保留窗口控制按钮，不再显示按钮旁的 `Work Review`。

## 9. 设置页：隐私设置

### 9.1 信息架构

隐私设置从“外层卡片 + 内层面板 + 手动分隔线”改为单层分组：

```text
隐私设置
活动记录和截图默认保存在本机；外部 AI 与远程存储按配置使用。

应用记录
3 条自定义规则 · 其他应用默认记录完整内容        添加规则

Chrome             只记录时长                  删除
1Password          不记录                      删除
VS Code            记录完整内容                删除

────────────────────────────────────────────

内容过滤
2 个敏感词 · 1 个黑名单域名                    展开
```

顶部说明必须准确，不再绝对声称所有数据都不会离开本机。

### 9.2 应用规则列表

- 规则改成紧凑列表行，不使用标签云。
- 应用名是主信息，策略是次级状态。
- 删除按钮始终可见，不依赖 hover。
- 删除操作使用红色；普通策略状态使用中性色文字和小圆点。
- 不使用大面积绿色、黄色和红色背景。
- 空状态提供简短说明和“添加规则”入口。

### 9.3 添加规则

点击“添加规则”后在应用记录分组内展开：

```text
选择应用
[搜索或输入应用名称]

运行中
[Chrome] [微信] [VS Code]

记录方式
[记录完整内容] [只记录时长] [不记录]

                              取消  添加
```

行为：

- 沿用现有保存接口和数据结构。
- 支持搜索/输入应用名以及选择运行中应用。
- 三种记录方式使用统一的分段选择样式。
- 选中态使用主色；语义色仅作为小型辅助标记。
- 提交成功后收起编辑区并刷新规则列表。
- 取消不保存草稿。

### 9.4 内容过滤

- 默认收起，只显示敏感词和黑名单域名数量摘要。
- 展开后沿用现有编辑能力，不改变后端结构。
- 输入项、删除入口、帮助文字使用与其他设置分组一致的尺寸和间距。

### 9.5 深色与响应式

- 外围与分隔边界使用共享中性 token。
- 不出现亮白线、双边框或明显内高光。
- 窄屏下规则行允许状态和操作换行，但应用名优先保持完整。
- 内联编辑区在窄屏改为单列；操作按钮放在内容末尾。

## 11. 测试设计

### 11.1 常驻网站

覆盖：

- 同一域名由 Chrome、Safari、Edge 访问时只生成一个域名条目。
- 域名总时长等于所有来源和未归属剩余量的合理聚合。
- 点击域名只展示该域名，不混入同一浏览器的其他网站。
- URL 跨浏览器聚合正确。
- 多浏览器占比与舍入结果合理。
- 单浏览器不展示多来源噪声。
- “查看全部”展示所有域名，不绑定首个浏览器。
- 跨日期统计不会因每日前 10 截断漏掉累计高频域名。
- 站点总数是真实总数。

### 11.2 今日节奏

覆盖：

- 分类分段可点击、可再次取消并支持键盘。
- 选中分类后摘要时长、占比、活跃时段和主要应用正确。
- 小时与分类组合选择结果正确。
- 切换日期清除过期选择。
- 隐私排除域名后顶部分类与小时明细口径一致。
- 横向模式状态、按钮和布局已移除。

### 11.3 页面轴与模型

覆盖：

- 助手和关于页头使用操作轴，主体仍使用阅读轴。
- 助手顶部模型标签随选择、异步配置加载和语言变化更新。
- 实际请求继续使用当前选中的模型配置。
- 生成中切换模型不会错误改写历史回答的模型语义。

### 11.4 隐私设置

覆盖：

- 规则以列表行渲染。
- 添加规则内联展开、取消和提交行为正确。
- 三种策略保存值保持现有契约。
- 内容过滤默认收起并显示正确数量。
- 删除操作始终可访问。
- 顶部隐私说明与外部 AI/远程存储能力不冲突。

### 11.5 验证命令

- 先运行新增和受影响的专项测试。
- 再运行前端完整测试，单次命令最多 60 秒。
- 运行 Rust 相关专项测试，单次命令最多 60 秒。
- 运行 `npm run build`，最多 60 秒。
- 在亮色、暗色、常见桌面宽度和窄屏下进行视觉检查。
- macOS 桌面壳验证原生标题隐藏且窗口按钮正常。

## 12. 验收标准

完成后必须同时满足：

1. 常驻网站不再混用图标和缩写。
2. 多浏览器访问同一域名时，列表和详情均表达完整来源。
3. 点击域名不会显示其他域名。
4. “查看全部”和站点数量是真正的全量语义。
5. 今日节奏分类构成可点击并显示轻量内联详情。
6. 今日节奏不再出现横纵切换按钮和 24 行横向布局。
7. 概览汇总类内容合理居中，结构化内容仍易于扫描。
8. 助手和关于页头与其他页面左上基线一致。
9. 助手底部选择非基础模型后，顶部不再错误停留在“基础模型”，并与当前选择同步。
10. macOS 窗口按钮旁不再显示 `Work Review`。
11. 隐私设置为单层、紧凑、易扫描结构，深色边界与概览一致。
12. 现有核心功能、隐私规则数据和 AI 请求流程无回归。
