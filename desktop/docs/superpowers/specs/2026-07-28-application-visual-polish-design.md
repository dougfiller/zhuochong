# Work Review 全应用外观轻量统一设计

**日期：** 2026-07-28  
**状态：** 待用户复核  
**范围：** 时段摘要展示顺序、全应用页面视觉一致性、设置页外层布局与响应式

## 1. 背景与目标

概览、日报、时间线、助手、设置和关于页面已经具备各自完整的功能与视觉结构，但页面内容轴、页头规格、深色边界、浮层外观和响应式规则仍存在细微差异。设置页尤其存在外壳层级偏多、宽屏内容过度拉伸、深色边界偏亮和窄屏导航占用空间过大的问题。

本次目标是在不重做应用、不改变功能结构的前提下，对整个应用进行一次轻量视觉统一，使界面保持：

- 干净、清爽、简单、好用。
- 页面明显属于同一套产品视觉体系。
- 能居中的容器合理居中。
- 高密度操作内容仍按语义左对齐。
- 深色模式不出现过亮外围线、重复边框或明显内高光。
- 改动集中在展示层和样式层，不改变现有数据契约。

## 2. 设计原则

### 2.1 统一规则，不强求所有页面完全相同

不同页面承担的任务不同：概览和时间线是数据工作台，设置是操作工作台，日报、助手和关于更偏阅读或交流。统一的是内容轴、页头基线、边界层级、留白和浮层规则，而不是让所有页面使用相同宽度或相同排版。

### 2.2 容器居中，内容按语义对齐

适合居中的内容：

- 品牌区域。
- 空状态。
- 汇总数字。
- 日报文章头。
- 短说明和简短原则。

保持左对齐或逻辑方向起点对齐的内容：

- 设置项和表单。
- 时间线记录。
- 日报正文。
- 助手回答。
- 表格、列表、长说明和高密度工具栏。

### 2.3 减少套壳和视觉噪声

一个页面区域原则上只保留一个主要内容边界。避免同一区域同时存在：

- 外围边框。
- 内高光。
- 重阴影。
- 渐变底板。
- 内部卡片的第二层明显边框。

### 2.4 语义色只承担语义

- 蓝色、靛青色：主操作、选中状态和页面导航。
- 琥珀色：时间线节点、分类和时段语义。
- 红色、玫红色：删除、危险操作和支持项目。
- 绿色：录制、成功和在线状态。
- 中性灰：普通卡片、输入框、按钮和分隔线。

大容器外围边界使用中性颜色，不使用大面积语义色染色。

## 3. 方案选择

### 方案 A：只修明显问题

仅处理时段摘要排序和设置页亮边。改动小，但无法改善全应用内容轴和页头不一致的问题。

### 方案 B：全应用轻量统一（采用）

保留应用壳、页面结构和功能，通过共享视觉规则、页面限宽、边界收敛、设置页简化和响应式统一完成优化。收益明显，风险可控。

### 方案 C：全面重做

重新设计应用壳和主要页面。工作量与风险过高，也不符合“不要复杂”的要求，因此不采用。

## 4. 时段摘要展示顺序

### 4.1 行为

时段摘要抽屉按小时倒序展示，最近时段排在最前：

```text
16:00 → 11:00 → 09:00
```

具体行为：

- 今天当前小时存在摘要时，当前小时排第一。
- 当前小时没有摘要时，最近一个有摘要的小时排第一。
- 历史日期按当天最晚有效时段到最早时段排列。
- 空状态、单条摘要和跨午夜显示规则保持不变。

### 4.2 技术边界

只在前端摘要抽屉展示层复制并排序数组：

```js
[...summaries].sort(
  (left, right) => Number(right.hour) - Number(left.hour)
)
```

不修改：

- 数据库 `ORDER BY hour ASC`。
- Rust 小时摘要接口排序。
- 本地 HTTP API 契约。
- 主时间线活动排序。
- 时间线分页和缓存结构。

### 4.3 测试边界

覆盖：

- 无序输入按小时倒序排列。
- 不修改原始数组。
- 当前小时缺失时最近小时排第一。
- 空数组、未传值和单条摘要。
- 数字字符串小时。
- `0` 点与 `23` 点边界。
- 抽屉实际遍历展示数组，而摘要统计继续使用完整集合。

## 5. 全应用页面视觉体系

### 5.1 三档页面内容宽度

#### 数据工作台

适用：概览、时间线。

- 保留较宽内容区域，充分利用窗口空间。
- 不强行缩成阅读页。
- 页面头和主要数据区域共用稳定的左右轴线。

#### 操作工作台

适用：设置。

- 建议最大宽度约 `78rem`。
- 页面工作台水平居中。
- 导航、表单、说明和输入内容按逻辑方向起点对齐。

#### 阅读与交流内容

适用：日报正文、助手对话、关于页主体。

- 使用约 `52rem` 至 `64rem` 的阅读宽度。
- 主体水平居中。
- 页头、上下文区域、正文或对话区尽量共用同一内容轴。
- 日报目录等辅助布局可以在宽屏时位于阅读内容之外。

### 5.2 页头基线

统一主页面页头的基础规格：

- 标题图标视觉尺寸。
- 标题字号和行高。
- 副标题颜色和行高。
- 页头与主体的垂直间距。
- 右侧操作按钮高度。
- 窄窗口下操作区换行规则。
- 页头与主体的左右内容轴。

允许保留页面差异：

- 日报正文日期标题继续居中。
- 助手保留会话标题与上下文状态。
- 设置保存按钮继续位于页头右侧并保持吸顶。
- 概览和时间线保留高密度日期与操作工具栏。

### 5.3 深色模式边界层级

建立或收敛为三档边界语义：

1. 弱分隔线：列表、段落和辅助区域。
2. 普通边界：卡片、输入框、按钮、Popover。
3. 强调边界：聚焦、选中、弹窗和需要强调的状态。

要求：

- 大容器外围线与概览现有中性深色边界保持一致。
- 删除接近白色的深色内高光。
- 同一表面不同时使用明显外边框和明显内高光。
- 时间线可以保留琥珀语义色，但大容器外围线回归中性边界。
- 助手、设置、抽屉、弹窗和 Popover 不再各自使用明显不同的灰度层级。

### 5.4 浮层分类

统一外围视觉，不改变功能结构：

- Popover：较小圆角、轻阴影、普通边界。
- Modal：中等圆角、统一遮罩、标题区和操作区层级。
- Drawer：统一右侧边界、背景、阴影和窄屏全屏规则。

现有日期选择器、分类修改、活动详情、时段摘要、支持项目、日报编辑和助手历史继续保留各自功能。

### 5.5 响应式基线

页面骨架优先围绕三类语义断点收敛：

- 紧凑窗口：约 `640px` 至 `700px`。
- 中等窗口：约 `920px`。
- 宽屏阅读布局：约 `1024px`。

不要求删除全部局部断点，但新增和调整的页面骨架规则优先使用以上基线。

## 6. 设置页专项设计

### 6.1 页面结构

保留现有结构：

```text
设置页头
└── 设置工作台
    ├── 设置分类导航
    └── 设置内容
```

不新增设置概览、快捷入口、摘要卡或额外导航层级。

### 6.2 工作台居中

- 页头与设置工作台使用一致的最大宽度，建议约 `78rem`。
- 整体水平居中。
- 表单和说明继续左对齐或逻辑方向起点对齐。
- 宽屏下避免输入框、标签和开关之间距离过大。

### 6.3 吸顶页头

保留：

- 吸顶能力。
- 标题和说明。
- 保存状态与保存按钮。

调整：

- 去掉独立大圆角悬浮卡效果。
- 去掉完整外围边框和明显阴影。
- 使用轻背景与底部分隔线。
- 深色分隔线使用与概览一致的低对比颜色。
- 保持浮层层级正确，不覆盖下拉、Popover 或 Modal。

### 6.4 内容外壳

`.settings-stage-shell` 只承担布局职责：

- 保留 `min-width: 0`。
- 保留纵向布局和内容间距。
- 移除明显背景、渐变、外围边框、内高光和阴影。

内部 `.settings-card` 成为主要内容边界，避免卡片套卡片。

### 6.5 分类导航

- 导航底板使用纯色或透明表面。
- 边界使用单层低对比线。
- 激活项使用单层浅色填充和清晰文字。
- 去掉横向位移动画、重渐变和明显内高光。
- 图标底板降低存在感。
- 使用逻辑方向对齐，兼容阿拉伯语。

### 6.6 窄屏导航

在约 `920px` 以下：

- 两列工作台改为单列。
- 设置分类变为横向单行滚动。
- 标签不收缩，当前项保持清晰。
- 焦点轮廓不能被滚动容器裁剪。
- 不改成下拉菜单，避免增加操作层级。

### 6.7 设置内容响应式

现有固定两列或三列区域在空间不足时逐级收敛：

- 小屏单列。
- 中屏两列。
- 空间充足时恢复三列。

重点检查：

- AI 能力入口。
- S3 配置。
- 存储统计。
- 本地 API 地址与端口。
- Bot 凭据。

危险操作、连接状态和代码示例等特殊区域可以保留独立容器。

## 7. 各页面调整边界

### 7.1 概览

- 作为全应用主要视觉参考。
- 保留现有数据工作台宽度和布局。
- 只在共享页头、边界变量或浮层规则需要时做最小调整。

### 7.2 时间线

- 保留时间轴、时间点、活动卡、摘要入口和详情抽屉。
- 实现时段摘要倒序。
- 大容器外围线使用中性边界。
- 琥珀色继续用于时间点、分类和时段语义。

### 7.3 日报

- 保留文章阅读形态、居中文章头、正文宽度和桌面目录。
- 仅统一页头基线、外围边界和浮层规格。

### 7.4 助手

- 保留全高工作台、滚动对话区、底部输入区和历史抽屉。
- 页头、上下文条、对话区与输入区尽量共用阅读内容轴。
- 深色参考范围、输入区和抽屉边界与概览的边界层级一致。
- 不改成普通卡片页面。

### 7.5 关于

- 保留品牌、版本、更新、产品原则、技术栈和支持项目。
- 主体和页头跟随同一阅读内容轴。
- 不增加常用入口。

### 7.6 桌面助手独立窗口

- 不套用主应用页面容器。
- 本次原则上不重做其结构。
- 仅在共享边界变量确实影响时验证视觉，不扩大功能范围。

## 8. A/B/C 外观风格

保留现有三套外观选项，不在本次重做每套页面。

调整方向：

- 页面背景、主表面、次级表面、普通边界、圆角和阴影优先使用共享变量或共享原语。
- 页面局部组件减少硬编码的独立边界与阴影。
- 三套风格下都不能出现重复卡片、边距塌陷或浅色边框泄漏。

## 9. 可访问性与国际化

- 设置导航和表单使用逻辑方向对齐，兼容 RTL。
- 横向导航保持键盘 Tab 可达。
- 当前设置分类具有明确的选中语义。
- 焦点轮廓不被 `overflow` 裁剪。
- 抽屉、Popover 和 Modal 的 Escape、焦点陷阱和焦点恢复行为保持不变。
- 中文、繁体中文、英文和阿拉伯语下不出现明显溢出或错误换行。

## 10. 测试与验证

### 10.1 自动化测试

按 TDD 实施，优先补充或更新：

- 时段摘要排序纯函数测试。
- 时段摘要抽屉接线测试。
- 全局页面宽度和内容轴样式约束。
- 设置页外壳、页头和横向导航样式约束。
- A/B/C 外观风格回归。
- 深色模式边界不泄漏浅色高光。
- 既有概览、时间线、日报、助手、设置和关于页面编辑约束测试。

### 10.2 构建与静态检查

- 单次测试或构建命令最大超时为 60 秒。
- 运行相关前端测试全集。
- 运行 Vite 生产构建。
- 运行定向 `git diff --check`。
- 不修改或清理用户已有的其他工作区改动。

### 10.3 视觉检查

重点尺寸：

- `1440px`。
- `1024px`。
- `920px`。
- `700px`。
- `640px`。

重点模式：

- 浅色与深色。
- 默认外观及 A/B/C 风格。
- 中文、英文和阿拉伯语关键布局。

## 11. 非目标

本次明确不包含：

- 重做应用壳或左侧主导航。
- 重做页面信息架构。
- 删除时间线结构。
- 改变日报正文阅读结构。
- 把助手改成普通卡片页面。
- 给关于页增加常用入口。
- 修改数据库结构或后端小时摘要排序契约。
- 修改业务数据、清理数据库或批量迁移配置。
- 重做桌面助手独立窗口。
- 更新依赖或引入新的 UI 框架。

## 12. 验收标准

1. 时段摘要按最近小时到最早小时展示，主时间线顺序不变。
2. 概览、时间线、日报、助手、设置和关于页面的页头与内容轴关系更一致。
3. 数据工作台、操作工作台、阅读内容三档宽度清晰，不强制所有页面同宽。
4. 深色模式大容器外围线与概览一致，不出现过亮边框和重复内高光。
5. 设置页整体居中，设置内容保持高效左对齐。
6. 设置页不再出现明显的外壳套外壳，设置卡片成为主要内容边界。
7. 约 `920px` 以下设置分类变为可键盘访问的横向滚动导航。
8. 浮层功能、焦点管理、国际化和现有业务行为保持不变。
9. 相关测试、生产构建和差异检查通过。
10. 不覆盖、不还原、不提交用户工作区中的其他改动。
