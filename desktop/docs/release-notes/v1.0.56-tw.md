# Work Review v1.0.56

**發布日期**：2026-07-23

## 新增

- **阿拉伯文支援（RTL）**（#128）：新增阿拉伯文介面翻譯 + RTL 佈局適配（CSS 邏輯屬性取代硬編碼方向），後端日報 / 分類名稱 / 活動時間線同步支援阿拉伯文輸出。社群貢獻 by algethamy。
- **MCP Server 功能增強**：
  - `get_current_context` 透過 localhost API 取得真實前景視窗（主應用執行時），不再僅回傳資料庫歷史紀錄；回退時標注 `"source": "history"`。
  - `generate_report` 在 AI 增強模式下委託主應用產生 AI 日報，尊重使用者的模型設定、工作時段、自訂 prompt 與隱私過濾。
  - 隱私過濾對齊主應用：MCP 查詢結果現支援 `Anonymized` 級別去識別化，與主應用的 `PrivacyFilter` 行為一致。
- **接入管理頁面重構**：將 997 行單檔拆分為容器 + 7 個子面板（`nodeGateway/`），分 3 組摺疊（AI 工具接入 / 訊息通知 / 進階）。飛書 / 釘釘 / 企業微信統一為泛型 `BotCredentialsPanel` 元件。
- **設計 Token 體系**：建立 `--radius-sm/md/lg`（8/12/20px）+ `--shadow-sm/md/lg` + `--space-section/block` 統一基準，app.css 中 35 處硬編碼值遷移至 token 變數。
- **localhost API `/v1/context` 端點**：回傳目前前景視窗 + 近期應用清單，供 MCP Server 委託呼叫。
- **工作助手 Token 串流輸出（階段 2）**：Agent 回答現按 token 逐字串流推送至前端（`StreamEvent::Token`，後端 64 位元組 / 100ms 批次合併降低 IPC 頻率），長回答不再「憋到最後一次蹦出」。四類 provider（OpenAI 相容 / Ollama / Claude / Gemini）各自實作 SSE/NDJSON 增量解析 + 工具呼叫分片拼裝，串流失敗自動回退非串流；請求格式轉換抽取為串流 / 非串流共用函式，逾時改為逐塊閒置 30s + 總時長 120s 雙護欄。新增 10 個組裝器 / 批次器單元測試。
- **工作助手聯網工具（階段 1）**：工具系統從「僅同步本地工具」擴展為支援非同步工具（`ToolExecutor::Sync/Async` 雙通道，5 個本地工具零改動），新增三個聯網工具——`fetch_url`（讀網頁正文，零相依）、`web_search`（支援 Tavily / 博查需配 Key，以及 DuckDuckGo / Bing 免費搜尋無需 Key）、`query_activities`（按日期查詢活動紀錄，專為「今天做了什麼」類問題設計，替代無法匹配相對時間的 FTS 搜尋）。移除了 `get_weather`（open-meteo 逾時頻繁，天氣改走 web_search）。預設全關，需在「設定 → AI 模型 → 助手聯網能力」顯式開啟（守住隱私預設關立場）；開啟後才把聯網設定傳入 Agent，問題才會發給搜尋服務商 / 目標網站。含 SSRF 護欄（攔本機 / 內網 / 鏈路本機位址，防止模型被誘導抓取本機 localhost API），聯網提示注入幫助小模型正確選工具。四語言 i18n + 單元測試覆蓋工具門控、SSRF、HTML 提取、搜尋格式化、非同步統一入口。

## 修復

- **創意類應用活動時長漏記**：PS/C4D 等創意軟體操作時畫面幾乎不變，但舊邏輯把「鍵鼠逾時 + 畫面靜止」判定為閒置導致丟時長。反轉雜湊判定語義：畫面靜止不再判閒置，僅鍵鼠 10 分鐘硬逾時兜底。
- **助手頁表格右側大空白**（#124 回歸）：`.assistant-markdown table` 仍為 `display:block`，窄內容表格右側留白。統一為 `display:table; width:100%`。
- **緊湊資料風格深色模式白邊**（#129）：`ui-style-c` 外框淺色 border + 半透明白底在深色模式下顯示為白邊。補齊 dark 覆蓋（border-color + box-shadow + background）。
- **深色模式白色高光線**（#129）：9 個元素（settings-tab-rail、ask-welcome-panel、overview-panel::before 等）的 `inset 0 1px 0 rgba(255,255,255,X)` 在深色下未被覆蓋。統一補齊 `box-shadow: none` 或 `display:none`。
- **深色模式原生控制項淺色**：新增 `color-scheme: light/dark`，原生 `<select>/<option>` 下拉清單在深色模式下正確渲染。
- **Windows 工作列不顯示應用名稱**（#129）：視窗標題為空字串導致工作列 / 工作檢視無名稱。設為 `"Work Review"`。
- **時間線節點未對齊時間軸**（#129）：軸線（absolute + calc）和節點（flex margin:auto）兩套獨立定位演算法差約 14px。統一為共享水平基準。
- **日報活動時間線表格斑馬紋誤傷**：details 內表格被全域 zebra striping + 表頭灰底覆蓋。補豁免規則。
- **亮色模式視覺不一致**：StatsCard 文字灰度統一為 slate-500；主卡片圓角極端值收斂（32px→28px）；卡片邊框統一為 `border-slate-200/80`。
- **設定頁 memoryHint 文案過時**：移除洞察卡片後文案仍提及「自動生成洞察」，改為描述 memory 實際功能。
- **助手串流事件從未抵達前端的兩處線格式錯誤**：`StreamEvent::Error(String)` 為內部標籤 + newtype 組合，serde 序列化直接失敗且被靜默吞掉，前端從未收到錯誤事件（改 struct 變體 `{ error }`）；`Done` 事件的 `tool_labels` 欄位以蛇形上線而前端讀 `event.toolLabels`（列舉頂層 rename_all 不作用於欄位），一直靠指令回傳值雙通道掩蓋（補欄位級 camelCase）。新增線格式契約測試鎖定。
- **停止記錄後兩處指示器仍顯示綠色脈衝**（#131）：概覽右上角「即時」圓點只判斷是否「今天」模式，時間軸「活動紀錄」圓點更是硬編碼綠色脈衝——兩處都沒回應錄製狀態。新增 `recordingStore`（參照 `assistantStore` 模式），App.svelte 在 `get_recording_state` 初始化與 `recording-state-changed` 事件中寫入 store，概覽 / 時間軸讀取 store 判斷圓點顏色：錄製中（綠 + 脈衝）/ 已停止（灰）。新增 7 個單元測試。
- **火山引擎（豆包）連線測試 URL 拼接錯誤**：連線測試的 `/v1` 回退邏輯假設所有 OpenAI 相容 API 的端點都以 `/v1` 結尾，但火山引擎用 `/api/v3`、智譜用 `/api/paas/v4`——這些已含版本段，不應再追加 `/v1`（會拼出 `/api/v3/v1/chat/completions` 這種不存在的端點，使用者報錯 `os error 10061` 根因）。修復 `openai_compatible_chat_completion_urls` 和 `fetch_openai_compatible_models`：識別任何版本號段（`/v1`～`/v9`）後不再回退。新增 3 個測試覆蓋火山引擎 v3 / 智譜 v4 / DeepSeek 無版本號三種情境。
- **助手頁配了模型卻預設用基礎模板**（#133）：使用者在設定頁設定好 AI 模型並測試通過後，助手頁的模型選擇器仍預設停在「基礎模板」而非已設定的模型——使用者不知道要手動切換下拉框，導致 AI 回答「我目前無法使用 AI 模型進行分析」。新增 `hasUserSelectedModel` 標誌：首次開啟助手頁且使用者從未手動操作過模型選擇器時，若存在已設定的模型設定檔，自動選中第一個；一旦使用者手動切換（含切回基礎模板），就尊重使用者選擇不再覆蓋。新增 3 個單元測試。
- **基礎模板模式下身份 / 能力類問答答非所問**：「你是誰」被路由到 FallbackPath，機械回答「我目前無法使用 AI 模型進行分析」。根因是 `route_query` 的閒聊觸發詞列表太窄（只有「你好 / hello / 幫助」），身份類問題（「你是誰 / 你是什麼 / who are you」）和能力類問題（「你能做什麼 / 介紹下自己」）全部漏網。統一修復：擴展 DirectPath 觸發詞覆蓋身份 / 能力問答；`direct_answer` 新增身份模板（介紹工作助手身份 + 提示目前模式）和能力模板；`fallback_answer` 文案改為引導性而非機械報錯（「這個問題我需要 AI 模型才能回答好」）。新增 5 個測試。
- **基礎模板模式大幅擴展工作查詢關鍵字覆蓋**：之前 `work_signals` 列表只收了某個說法的單一表達（如「做了什麼」但不收「幹了什麼」，「應用」但不收「軟體」），導致大量常見工作查詢問法（「忙不忙」「摸魚了嗎」「資料怎麼樣」「開會開了多久」「在幹嘛」等 15+ 種）落到 FallbackPath 給引導文案。按同義詞家族擴展：做 / 幹 / 搞、忙、資料 / 情況 / 概覽、專注 / 產出 / 摸魚 / 下班、app / 軟體 / 程式、多久 / 小時、開會 / 會議、小結 / 匯總、幹嘛 / 幹什麼。同時 `fast_answer` 在無時間詞時預設查「今天」（而非全量 10000 條），讓「小結」「資料如何」等無時間詞查詢更聚焦。新增 1 個測試覆蓋 15 種擴展問法。
- **日報提示詞預設編輯**（#130）：日報頁面的提示詞預設下拉選單新增編輯按鈕（鉛筆圖示），使用者可以直接修改已有預設的名稱和內容，而不必刪除後重建。編輯儲存邏輯區分「新建」與「更新」兩種情境。
- **設定檔原子寫入與故障安全啟動**：設定載入 / 儲存改為原子操作（暫存檔 + rename + fsync），寫入前自動備份上一版本（`.bak`），暫存檔透過 RAII 在所有路徑（含錯誤 / panic）自動清理。啟動時若主設定損壞，從備份還原或以故障安全預設值（關閉所有採集 / 權限 / 遠端）啟動，保留損壞現場供排查。支援 4 種狀態（Loaded / Missing / RecoveredFromBackup / Corrupted），故障狀態下跳過權限初始化和自動寫回。Unix 暫存檔權限 0600 防符號連結劫持。新增覆蓋四態組合、原子覆蓋寫、備份生成、父目錄 sync 失敗等情境的測試。
- **MCP Server localhost 請求認證**：MCP Server 對 localhost API 的所有請求現在攜帶 Bearer token 認證（從 `localhost_api_token.txt` 讀取）。fail-closed 設計——token 缺失或格式非法時不發請求，降級到本地模板 / 歷史資料。每次請求重讀 token 檔案，支援主應用輪替後即時生效，無需重啟 MCP。2 秒逾時，請求失敗不阻塞 MCP 主流程。
- **Bot 日報生成 API 對齊**：IM Bot（Telegram / 飛書 / 企業微信 / 釘釘）觸發的日報生成改為走標準 localhost API（`POST /v1/reports/generate`，JSON body），替代舊的查詢字串拼接。鑑權從 URL token 升級為 Bearer header（token 不再暴露在 URL / 存取日誌裡）。服務端同時保留 GET（query）和 POST（JSON body）兩條路徑，舊版 bot 仍可相容。

## 優化

- **日報頁面視覺重設計**：去玻璃擬態 + 斜紋紋理，改極簡現代風（統一 token、輕陰影、大留白、統計卡重做、表格去重陰影 + zebra、活動時間線摺疊樣式現代化）。
- **助手多輪對話攜帶工具歷史軌跡**：歷史 payload 此前只發 `{role, content}`，丟掉了工具步驟資訊，導致下一輪模型重走上一輪失敗的工具（例如上輪 `search_memory` 0 條後下輪又先調 `search_memory`）。現在 assistant 訊息若含已完成工具步驟，會以緊湊內聯摘要追加到 content 尾部再發後端。摘要按工具類型區分，避免數字誤導：
  - 失敗工具：`web_search↯`（最強「別再試」信號）
  - `search_memory`：`search_memory→0条`（references 僅它貢獻，hits 有真實語義）
  - 其他成功工具：`query_activities✓` / `fetch_url✓`（不寫數字，因為它們的 hits 恆為 0——`collect_references` 全專案僅 search_memory 呼叫一次）
  - 範例：`[工具：search_memory→0条 | query_activities✓ | web_search↯]`
  - system prompt 增加宣告，告知模型這種方括號片段是機器摘要、不要複述給使用者（4 個 locale 各自翻譯，加在 `ask.rs` 的 `build_assistant_system_prompt` 末尾——該函式是生產路徑 `chat_work_assistant` 唯一呼叫的 prompt 源；之前曾誤加在 `executor.rs` 的 `DEFAULT_SYSTEM_PROMPT`，但生產路徑 `unwrap_or` 永遠走不到，是死代碼，已修正）
  - 同時：後端 `StepResult` 事件增加 `ok: bool` 欄位區分真正失敗 vs 成功但 0 引用；前端跳過串流或失敗的半截輪次；補齊端到端「防重走失敗路徑」、舊事件三態相容和各 locale system prompt 契約測試。
- **助手串流請求隔離與可靠投遞**：每次回答按 assistant 訊息 ID 定點更新，並以 `sendingRequestId` 綁定發送佔用；頁面卸載後可立即開始新請求，舊請求的遲到事件和 finally 不會污染或釋放新請求。Token 增量仍允許在背壓時丟幀，`StepStart` / `StepResult` / `Done` 則透過內部 ACK 等待 Tauri Channel 實際發送成功；橋接失敗會向 Agent 傳播並取消已在途的模型 / 工具 Future，且不會誤走 FastPath。
- **工具計數測試斷言修復**：移除 `get_weather` 後基礎工具數從 5 變 6，但 `test_openai_tools_format_is_valid` 的斷言未同步更新，已修正。
