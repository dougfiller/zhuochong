# Work Review v1.0.56

**Release date**: 2026-07-23

## New

- **Arabic support (RTL)** (#128): Added Arabic UI translation + RTL layout adaptation (CSS logical properties replacing hardcoded direction); the backend report / category names / activity timeline now also support Arabic output. Community contribution by algethamy.
- **MCP Server enhancements**:
  - `get_current_context` now fetches the real foreground window via the localhost API (when the main app is running), instead of only returning DB history; the fallback path tags `"source": "history"`.
  - `generate_report` in AI-enhanced mode delegates to the main app to produce an AI daily report, respecting the user's model config, working hours, custom prompt, and privacy filter.
  - Privacy filtering aligned with the main app: MCP query results now support `Anonymized`-level masking, matching the main app's `PrivacyFilter`.
- **Connection-management page refactor**: Split the 997-line single file into a container + 7 sub-panels (`nodeGateway/`), grouped into 3 collapsible sections (AI tool integrations / notifications / advanced). Feishu / DingTalk / WeCom are unified into a generic `BotCredentialsPanel`.
- **Design-token system**: Established `--radius-sm/md/lg` (8/12/20px) + `--shadow-sm/md/lg` + `--space-section/block` baselines; migrated 35 hardcoded values in app.css to token variables.
- **localhost API `/v1/context` endpoint**: Returns the current foreground window + recent app list, for the MCP Server to call.
- **Work Assistant token streaming (phase 2)**: Agent answers now stream to the frontend token-by-token (`StreamEvent::Token`; backend batches at 64 bytes / 100ms to cut IPC rate), so long answers no longer appear all at once at the end. All four providers (OpenAI-compatible / Ollama / Claude / Gemini) implement their own SSE/NDJSON incremental parsing + tool-call shard assembly, with automatic non-streaming fallback; request-format conversion was extracted into shared streaming/non-streaming helpers, and timeouts became dual-guarded (per-chunk idle 30s + total 120s). Added 10 assembler/batcher unit tests.
- **Work Assistant web tools (phase 1)**: The tool system grew from "sync-only local tools" to also support async tools (`ToolExecutor::Sync/Async` dual channel; the 5 local tools needed zero changes), adding three web tools — `fetch_url` (reads page body, zero-dependency), `web_search` (Tavily / Bocha with a key, or DuckDuckGo / Bing free search without one), and `query_activities` (queries activity records by date, designed for "what did I do today"-style questions, replacing FTS search that can't match relative time). Removed `get_weather` (open-meteo timed out often; weather now goes through web_search). All off by default; you must explicitly enable them under Settings → AI Model → Assistant web capabilities (keeping privacy default-off). Only after enabling is the web config passed to the Agent, so questions are only sent to search providers / target sites. Includes SSRF guardrails (blocks localhost / private network / link-local addresses, preventing the model from being coaxed into fetching the local API) and a web-tool hint injected to help small models pick the right tool. Four-language i18n + unit tests covering tool gating, SSRF, HTML extraction, search formatting, and the async unified entry.

## Fixes

- **Creative-app activity time under-counted**: Creative software like PS/C4D barely changes the screen, but the old logic treated "mouse/keyboard timeout + static screen" as idle, dropping time. Reversed the hash semantics: a static screen no longer counts as idle; only the 10-minute mouse/keyboard hard timeout remains as a fallback.
- **Large blank on the right of assistant tables** (#124 regression): `.assistant-markdown table` was still `display:block`, leaving whitespace beside narrow tables. Unified to `display:table; width:100%`.
- **Compact-data style dark-mode white edge** (#129): The `ui-style-c` outer frame's light border + translucent white background showed as a white edge in dark mode. Added dark overrides (border-color + box-shadow + background).
- **Dark-mode white highlight lines** (#129): 9 elements (settings-tab-rail, ask-welcome-panel, overview-panel::before, etc.) had `inset 0 1px 0 rgba(255,255,255,X)` not overridden in dark mode. Unified to `box-shadow: none` or `display:none`.
- **Light-themed native controls in dark mode**: Added `color-scheme: light/dark` so native `<select>/<option>` dropdowns render correctly in dark mode.
- **Empty Windows taskbar name** (#129): An empty window title left the taskbar / Task View unnamed. Set to "Work Review".
- **Timeline nodes misaligned with the axis** (#129): The axis (absolute + calc) and nodes (flex margin:auto) used two independent positioning algorithms, ~14px apart. Unified onto a shared horizontal baseline.
- **Report timeline table zebra-striping hit by mistake**: Tables inside `<details>` were caught by global zebra striping + grey header. Added an exemption rule.
- **Light-mode visual inconsistency**: StatsCard text greys unified to slate-500; main-card corner-radius extreme value reined in (32px→28px); card borders unified to `border-slate-200/80`.
- **Outdated settings memoryHint copy**: After removing the insight card, the copy still mentioned "auto-generated insights". Rewritten to describe what memory actually does.
- **Two on-wire format bugs that kept streaming events from ever reaching the frontend**: `StreamEvent::Error(String)` was an internal-tag + newtype combo that serde failed to serialize, and the error was silently swallowed, so the frontend never got error events (changed to a struct variant `{ error }`); the `Done` event's `tool_labels` field shipped snake_case while the frontend read `event.toolLabels` (enum-level `rename_all` doesn't apply to fields), hidden only because the command return value covered it (added field-level camelCase). Added wire-format contract tests.
- **Two indicators still pulsing green after stopping recording** (#131): The overview's "live" dot only checked for "today" mode, and the timeline "activity" dot hard-coded a green pulse — neither responded to recording state. Added a `recordingStore` (mirroring `assistantStore`); App.svelte writes to it on `get_recording_state` init and `recording-state-changed` events; overview/timeline read it for dot color: recording (green + pulse) / stopped (grey). Added 7 unit tests.
- **Volcengine (Doubao) connection-test URL bug**: The `/v1` fallback assumed every OpenAI-compatible endpoint ends in `/v1`, but Volcengine uses `/api/v3` and Zhipu uses `/api/paas/v4` — these already contain a version segment and shouldn't get `/v1` appended (it produced non-existent endpoints like `/api/v3/v1/chat/completions`, the root cause of the user's `os error 10061`). Fixed `openai_compatible_chat_completion_urls` and `fetch_openai_compatible_models`: once any version segment (`/v1`–`/v9`) is detected, no fallback is applied. Added 3 tests covering Volcengine v3 / Zhipu v4 / DeepSeek no-version.
- **Assistant page defaulted to the basic template even with a model configured** (#133): After a user configured and tested an AI model in Settings, the assistant's model selector still defaulted to "basic template" instead of the configured model — the user didn't know to switch the dropdown, so the AI replied "I can't use an AI model right now". Added a `hasUserSelectedModel` flag: on first open, if the user has never touched the selector and a configured model profile exists, auto-select the first one; once the user manually switches (including back to basic template), respect their choice and don't override. Added 3 unit tests.
- **Off-topic identity/ability answers in basic-template mode**: "Who are you" was routed to FallbackPath, mechanically replying "I can't use an AI model". Root cause: `route_query`'s chitchat trigger list was too narrow (only "hello/你好/help"); identity ("who are you / what are you") and ability ("what can you do / introduce yourself") questions all slipped through. Unified fix: expanded DirectPath triggers to cover identity/ability Q&A; `direct_answer` gained identity (introduce the work assistant + note current mode) and ability templates; `fallback_answer` copy became guiding instead of a mechanical error ("this one needs an AI model to answer well"). Added 5 tests.
- **Greatly broadened work-query keyword coverage in basic-template mode**: The old `work_signals` list only collected one phrasing per idea (e.g. "做了什么" but not "干了什么", "应用" but not "软件"), so many common work queries ("busy?", "slacking off?", "how's the data?", "how long was the meeting?", "what am I doing?", 15+ forms) fell through to FallbackPath's guidance. Expanded by synonym families: do/work/搞, busy, data/status/overview, focus/output/slacking/off-work, app/software/program, how-long/hours, meeting, summary/recap, what's-up/doing-what. Also `fast_answer` now defaults to "today" (not the full 10000 rows) when no time word is present, focusing "summary" / "how's the data" queries. Added 1 test covering 15 expanded forms.
- **Report prompt-preset editing** (#130): The report page's prompt-preset dropdown gained an edit button (pencil icon); users can now edit an existing preset's name and content instead of deleting and recreating it. The save logic distinguishes "create" vs "update".
- **Atomic config writes + fail-safe startup**: Config load/save is now atomic (temp file + rename + fsync); before writing, the previous version is backed up (`.bak`); temp files are cleaned up via RAII on all paths (incl. errors/panic). On startup, if the main config is corrupted, it recovers from backup or boots into fail-safe defaults (all collection / permissions / remote off), keeping the corrupted file for diagnosis. Four states supported (Loaded / Missing / RecoveredFromBackup / Corrupted); in a fault state it skips permission init and auto-save. Unix temp-file permission 0600 prevents symlink hijacking. Added tests covering the four states, atomic overwrite, backup generation, and parent-dir sync failure.
- **MCP Server localhost request auth**: All MCP Server requests to the localhost API now carry a Bearer token (read from `localhost_api_token.txt`). Fail-closed — if the token is missing or malformed, no request is sent and it degrades to local template / history data. The token file is re-read each request, so rotation in the main app takes effect immediately without restarting the MCP. 2s timeout; a failed request doesn't block the MCP main flow.
- **Bot report-generation API alignment**: The IM bot (Telegram / Feishu / WeCom / DingTalk) report generation now goes through the standard localhost API (`POST /v1/reports/generate`, JSON body), replacing the old query-string concatenation. Auth upgraded from a URL token to a Bearer header (token no longer exposed in URLs / access logs). The server keeps both GET (query) and POST (JSON body) paths, so old bots stay compatible.

## Improvements

- **Report page visual redesign**: Dropped glassmorphism + diagonal textures for a minimalist modern look (unified tokens, light shadows, generous whitespace, redone stat cards, de-duplicated table shadows + zebra, modernized collapsed activity-timeline style).
- **Assistant multi-turn carries tool history**: The history payload previously sent only `{role, content}`, dropping tool-step info, so the next-turn model retried the previous turn's failed tools (e.g. after `search_memory` returned 0, it would call `search_memory` again first). Now, if an assistant message contains completed tool steps, a compact inline summary is appended to the content's tail before sending. The summary is per tool-type to avoid misleading numbers:
  - failed tool: `web_search↯` (strongest "don't retry" signal)
  - `search_memory`: `search_memory→0条` (only it contributes references; hits carry real semantics)
  - other successful tools: `query_activities✓` / `fetch_url✓` (no number, since their hits are always 0 — `collect_references` is called once project-wide, only by search_memory)
  - example: `[工具：search_memory→0条 | query_activities✓ | web_search↯]`
  - the system prompt now declares these bracketed snippets are machine summaries the model shouldn't repeat to the user (translated per locale, appended to the end of `build_assistant_system_prompt` in `ask.rs` — the only prompt source the production path `chat_work_assistant` calls; previously mis-added to `DEFAULT_SYSTEM_PROMPT` in `executor.rs`, which the production `unwrap_or` never reaches — dead code, now fixed)
  - also: the backend `StepResult` event gained an `ok: bool` field to distinguish real failure vs success-with-0-references; the frontend skips streaming or half-finished failed turns; backfilled end-to-end "don't redo failed paths", old-event three-state compat, and per-locale system-prompt contract tests.
- **Assistant streaming isolation & reliable delivery**: Each answer is pinned to its assistant message ID for updates, with the send slot bound by `sendingRequestId`; after the page unloads a new request can start immediately, and late events / finally from the old request won't pollute or release the new one. Token increments can still drop frames under backpressure, while `StepStart` / `StepResult` / `Done` wait on an internal ACK for the Tauri Channel to actually send; a bridge failure propagates to the Agent and cancels in-flight model/tool Futures, without misrouting to FastPath.
- **Tool-count test assertion fix**: After removing `get_weather` the base tool count went 5→6, but `test_openai_tools_format_is_valid`'s assertion wasn't updated — now fixed.
